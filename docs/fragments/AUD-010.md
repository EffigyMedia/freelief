### AUD-010 - Nothing checks that a change to a shipped file comes with a version bump, so installed users can keep an old file, including a changed crisis line, indefinitely

- Severity: Medium
- Area: H. Build & deployment readiness
- Evidence: Quoted this round (UNT-010). sw.js: `const CACHE = `freelief-${self.FREELIEF_VERSION}`;` and fetch answers `caches.match(event.request, { ignoreSearch: true }).then((cached) => cached || fetch(event.request))`, cache first, so a file changes for an installed user only when version.js changes. The technical reference app_shell_and_offline.md only says: "add every new shipped file to `FILES` and bump the version so the cache is replaced." The only version test is test_version_has_one_valid_home ("assert freelief.read_version() is not None"). No test, no doctor check and no build check compares the shipped files against the version. Design decision 7: "Rollback is a revert commit." AGENTS.md also allows a push "when the owner needs a build to test on the phone", which is not a release and has no bump step. (quoted in round UNT-010)
- Impact: A push that fixes a crisis-line number in data/crisis-lines.json or strings but forgets version.js deploys a fix that no installed user ever receives; the worker byte-check sees no change, and they keep the old, possibly out-of-service, number with no sign that it is stale. A revert commit that does not move version.js forward leaves installed users on the broken version. Crisis-line data is named safety-critical in AGENTS.md.
- Direction: Add a check to `test` (or `build`) that hashes the shipped files and compares the hash with one recorded for the current version (for example a small committed file, or a content hash in version.js), or compares the shipped files with the last commit that changed version.js, and fails when the files changed and the version did not. State the rule in AGENTS.md under Conventions. State in the design's rollback line that a rollback is a revert plus a forward version bump.
