### AUD-007 - The design's control against a tampered crisis line ('every change goes through a reviewed commit') is not in place

- Severity: Medium
- Area: E. Security
- Evidence: Design, Security and privacy: "a tampered crisis line (every change goes through a reviewed commit)". `gh api repos/EffigyMedia/freelief/branches/main/protection` returned `Branch not protected (HTTP 404)`. `gh api repos/EffigyMedia/freelief/rulesets` returned `[]`. `.github/` has no workflow. AGENTS.md: "a push is a deploy". `sw.js` calls `self.skipWaiting()` and `self.clients.claim()`, so a pushed version takes over installed copies at once. No test pins crisis-line numbers: `test_every_crisis_line_is_dated_and_dialable` checks only that a `tel:` link and a date exist. (quoted in round UNT-010)
- Impact: A stolen GitHub credential, including the gh token on this machine, or a mistaken push can change a crisis number. The change goes live for every user on the next load, and the old number is not kept. Nothing reviews the change or catches it. The design states a control that does not exist.
- Direction: Add a ruleset on `main` that blocks force push and deletion and requires a pull request, or signed commits, as the owner chooses. Add a test that compares each line in `data/crisis-lines.json` with a reviewed record (number, source, date), so that a changed number fails unless its record also changes. Or, if the owner rules that no enforced review is wanted, rewrite the design clause to state the real control, with a Decision Log entry.
- Effort: M
- Found by: the security lens of round [[UNT-010]].
