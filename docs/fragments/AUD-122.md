### AUD-122 - Stopping the `run` wrapper can leave its child http.server running on port 8000

- Severity: Low
- Area: H. Build and deployment readiness
- Evidence: tools/freelief.py cmd_run: `return subprocess.run([sys.executable, "-m", "http.server", str(PORT), "--bind", "127.0.0.1"], cwd=ROOT).returncode`. The health check reports: 'when the wrapper was stopped, its child python -m http.server 8000 kept running and kept port 8000 bound (PID 8548, ended by hand)'. On Windows, the child is not ended when the parent is terminated, unlike with Ctrl+C in a console. (quoted in round UNT-104)
- Impact: This hurts the owner and later sessions. A stray server keeps serving an old working tree on port 8000, so a later `run` fails to bind, or a browser check reads a stale server. The effect is local only and contained.
- Direction: Serve in the same process: call http.server's ThreadingHTTPServer directly from cmd_run, so there is no child process. Alternatively, start the child in a Windows job object, or kill it in a finally block.
- Effort: S
