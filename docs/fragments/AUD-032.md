### AUD-032 - setup installs the test dependencies unpinned and with no lock file

- Severity: Low
- Area: E. Security
- Evidence: tools/freelief.py: `PIP_PACKAGES = ("playwright", "axe-playwright-python")` and `subprocess.run([tool, "pip", "install", "--python", str(VENV), *PIP_PACKAGES], ...)`. There is no version pin, hash, requirements or lock file in the repository. The venv now has playwright 1.63.0 and axe-playwright-python 0.1.8 only because those were the latest versions on the day `setup` ran. (quoted in round UNT-010)
- Impact: Each `setup` on a new machine installs whatever version is newest. A compromised or broken release of either package runs on the owner's machine, where the gh token and the push rights live. A test result is not reproducible across machines or months, and a breaking Playwright release would surface as unexplained test failures. Nothing ships, so users are not touched directly.
- Direction: Pin both packages to exact versions (`playwright==1.63.0`, `axe-playwright-python==0.1.8`), or keep a hashed requirements or uv lock file that `setup` installs from. Declare them in `tools.toml`, and have doctor report the installed versions.
- Effort: S
- Found by: the security and operations lenses of round [[UNT-010]] - convergence.
