### AUD-185 - test_calm.py holds an invalid escape sequence in a non-raw string, which Python reports on every doctor and test run and which a later Python will refuse

- Severity: Low
- Area: C. Regression risks
- Evidence: Round UNT-155. tools/tests/test_calm.py, in the thunder test: `probe = """` ... `if (!/config\.json/.test(String(input.url || input))) return response;` inside a non-raw triple-quoted string. Health step: doctor and test both printed 'tools\tests\test_calm.py:415: SyntaxWarning: "\." is an invalid escape sequence'. A commit in this line already fixed the same class of defect elsewhere: e1b43a2 'Make the hostile-data test's script a raw string'. (quoted in round UNT-155)
- Impact: Today it is only noise on every run. When Python makes invalid escapes a SyntaxError, test_calm.py stops loading. The runner then reports it as '[FAIL] test_calm.py: could not load', and every Kaleidoscope and rain test is lost until someone fixes the string. The failure is loud, not silent.
- Direction: Make the probe a raw string (`r"""..."""`) or write `\\.`. Make doctor's compile step treat a SyntaxWarning as a failure, for example with `warnings.simplefilter("error", SyntaxWarning)` around compile(), so the next one is caught at Resume.
- Effort: S
- Found by: the operations lens of round [[UNT-155]].
