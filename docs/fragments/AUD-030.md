### AUD-030 - The stored-settings check accepts inherited object names, so a stored rhythm of 'constructor' breaks the breathing guide

- Severity: Low
- Area: E. Security
- Evidence: settings.js: `if (stored.rhythm in config.breathing.rhythms) values.rhythm = stored.rhythm;`. The rhythms object comes from JSON, so `"constructor" in rhythms` is true. Probe: with `localStorage` set to `{rhythm:'constructor'}` and a reload, the page reached `ready= true` but logged `Cannot read properties of undefined (reading 'key')`, and the guide text was `Breathe |  | Pause`, with no phase shown. The code comment claims "blocked or broken storage never breaks a screen: the defaults from config.json stand (REQ-023)". (quoted in round UNT-010)
- Impact: Only a same-origin writer can set this value: the person's own browser tools, or one of the three sibling sites on the shared origin (see the shared-origin finding). The result is a breathing screen that does not guide, at launch.
- Direction: Use `Object.hasOwn(config.breathing.rhythms, stored.rhythm)` or `config.breathing.rhythmOrder.includes(stored.rhythm)`. Extend the settings round-trip test with a stored value that is an inherited name.
- Effort: S
- Found by: the security lens of round [[UNT-010]].
