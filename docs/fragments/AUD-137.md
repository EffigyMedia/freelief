### AUD-137 - The crisis-line freshness check accepts a checked date in the future

- Severity: Low
- Area: C. Edge cases
- Evidence: Quoted in this round. tools/freelief.py stale_crisis_checks(): 'age = (today - datetime.date.fromisoformat(checked)).days' and then 'if age > max_age_days: stale.append(...)'. A date after today gives a negative age, which is never stale. test_repo.py tests only a far-future today ('far_future = datetime.date(2100, 1, 1)'), not a future checked date. Every line now carries '"checked": "2026-10-07"'. (quoted in round UNT-124)
- Impact: A typing error such as 2027-10-07 in safety-critical crisis data makes that line pass both doctor and build --release for over a year without a re-check. The help dialog then shows that date to the person as the last check.
- Direction: Treat a checked date after today as invalid in stale_crisis_checks ('in the future'), so that doctor warns and build --release fails. Add a test for it.
- Effort: S
- Found by: the operations lens of round [[UNT-124]].
