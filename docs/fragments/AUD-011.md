### AUD-011 - test and build check the working tree, not the commit that GitHub Pages deploys

- Severity: Medium
- Area: H. Build & deployment readiness
- Evidence: Quoted this round (UNT-010). tools/freelief.py shipped_files: `subprocess.run(["git", "ls-files", "--cached", "--others", "--exclude-standard"], ...)` with the docstring "Every tracked or new file". test_offline compares sw.js FILES with that set, and harness.py serves `directory=str(ROOT)`, the working tree. The health check saw an untracked file (tools/icon_drafts.py) appear during the run. AGENTS.md: "GitHub Pages serves main ... A push deploys". (quoted in round UNT-010)
- Impact: A new shipped file that is added to FILES and imported by app.js but left out of the commit passes `test`, `build` and `bench` locally. On Pages it returns 404: the module import fails (blank page), and `cache.addAll(FILES)` rejects, so the new worker never installs and no new visitor gets offline use. The release gate 'verify test is green' does not prove the deployed commit works.
- Direction: Make `build` and the cache-list test use `git ls-files --cached` only and fail when an untracked or modified file sits in a shipped path, or run the release checks against a clean `git worktree` of the commit to be pushed. Say in the Release row that `test` runs on a clean tree.
- Effort: S
- Found by: the operations lens of round [[UNT-010]].
