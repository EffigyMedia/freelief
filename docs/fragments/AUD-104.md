### AUD-104 - Crisis-line freshness is checked only at a release, so nothing notices a line going stale on the live site between releases

- Severity: Medium
- Area: C. Reliability & operations
- Evidence: Quoted in round UNT-082. stale_crisis_checks(config["crisis"]["maxCheckAgeDays"]) runs only in `build --release` (tools/freelief.py). config.json has "maxCheckAgeDays": 90. Design risk table: "A crisis line in the list goes out of service. | Each line has a last-checked date; a release re-checks every line". AGENTS.md: "From 1.0 on, `live` moves only at a release". The app only displays the date (`t("help.checked", { date: line.checked })`). No scheduled check, doctor check or test compares the live data with the window. (quoted in round UNT-082)
- Impact: If no release happens for months, which the strict release gate makes likely, the safety-critical lines in the live app and in every installed copy age past 90 days with no prompt to the owner. A person in danger may be shown a number that no longer works.
- Direction: Make a stale crisis check visible outside releases. For example, make doctor (which Resume runs) warn when a line in the version on `live` is older than maxCheckAgeDays. Or record a dated owner duty with a due date. Write the rule into the design's risk table.
- Effort: S
- Found by: the omission lens of round [[UNT-082]].
