### AUD-181 - Design section 9 says a planted cache 'is deleted at the next update', but when freelief~state is missing the worker keeps the highest-named cache, planted or not

- Severity: Low
- Area: E. Security - permissions against the design's authorization model (the shared-origin bound)
- Evidence: Quoted in this round. Design section 9: 'each activation keeps only the cache of the version it replaced (recorded in `freelief~state`), so a cache another site plants under a version's name is never served by address and is deleted at the next update.' sw.js activate: `const keep = replaced ? `${PREFIX}${replaced}` : valid.at(-1);`. sw.js `replacedVersion()` returns null when the `freelief~state` entry is absent: `.then((entry) => (entry ? entry.text() : null))`. The sw.js header says sibling workers 'may delete caches they do not own' (AUD-014), and `freelief~state` is one of those caches. There is also no record on the first activation of a 0.8.28+ worker over an older one. live moved from preview-0.8.22 to preview-0.8.32, so every installed preview took that path once. In either case, a planted `freelief-999.0.0` sorts highest and is kept, and the real previous version's cache is deleted. The AUD-157 fix note itself says 'with no record, the highest valid version is kept once' and 'freelief~state itself sits on the shared origin'. The design sentence states neither. The part that matters for safety does hold: in this round, a mutation test showed that a planted cache is never served by address. (quoted in round UNT-155)
- Impact: No person sees planted content: the ?v= guard holds without the record. The security clause of the design overstates a guarantee. Assume a sibling-site defect deletes or rewrites `freelief~state` and a planted cache exists. Then the planted cache survives the next update, and it displaces the real previous version's cache, which AUD-057 keeps for an open old page. That page's lazy screens then load from the new version's cache, which is the mix AUD-057 prevents. The reach is small. The cost is that a later reader trusts the sentence as an unconditional property.
- Direction: In design section 9, replace 'is deleted at the next update' with a statement of what the code does. A planted cache is never served by address. It is deleted at the next update while `freelief~state` holds the replaced version. When that record is missing (the first update from a version before 0.8.28, or after another site deletes it), the highest valid version name is kept for one update. Alternatively, when there is no record, keep no other cache. The cost of that is only the AUD-057 protection for that one update. Then delete the sentence it replaces in the same edit.
