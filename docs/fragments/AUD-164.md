### AUD-164 - An interrupted refresh leaves a 'freelief~refresh-<version>' cache that no later version deletes, because activate deletes only names that start with 'freelief-'

- Severity: Low
- Area: D. Memory; omission (an object with no end)
- Evidence: Quoted in round UNT-139. sw.js: "const temporary = `freelief~refresh-${self.FREELIEF_VERSION}`;" and "The temporary name does not start with PREFIX, so no cleanup reads it as a version." activate filters `keys.filter((key) => key.startsWith(PREFIX) && key !== CACHE)` with PREFIX "freelief-". The temporary cache is deleted only at the end of its own promise chain (a successful refresh), or at the start of the next refresh of the same version. If the worker is stopped during a refresh, the cache stays. After the next update the version in its name never refreshes again, so nothing deletes it. test_offline.py checks only that the cache is gone after a successful refresh. (quoted in round UNT-139)
- Impact: If the browser kills the worker during a refresh (the app closed, or the phone reclaims memory), a full copy of the app (about 240 KB) stays in Cache Storage on the origin that Freelief shares with other sites. Each version that is interrupted this way leaves one more copy, and nothing ever removes them. This takes storage quota from the offline copy, which the browser can evict under pressure (AUD-080).
- Direction: In `activate`, also delete every key that starts with "freelief~refresh-" and is not for this version. Add to the existing update test a case that creates such a stale cache and asserts that it is gone after activation.
- Effort: S
