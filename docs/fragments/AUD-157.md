### AUD-157 - The service worker takes a cache name from the request's ?v= query with no check, for navigations too, and activation never deletes the highest-named freelief- cache, so a planted cache stays reachable by a link through every update

- Severity: Medium
- Area: E. Security - input validation at trust boundaries
- Evidence: Quoted in round UNT-139. sw.js fetch handler: `const asked = url.searchParams.get("v"); const own = asked && asked !== self.FREELIEF_VERSION ? `${PREFIX}${asked}` : CACHE;` and then `caches.has(own).then((kept) => caches.open(kept ? own : CACHE))`. Nothing checks the form of `v`, and nothing limits it to the lazy-screen script requests that app.js makes (`import(`./exercises/breathe.js?v=${VERSION}`)`). sw.js activate: `const others = keys.filter((key) => key.startsWith(PREFIX) && key !== CACHE).sort(...compareVersions...); return Promise.all(others.slice(0, -1).map((key) => caches.delete(key)));`, so the highest-sorting other freelief- cache is never deleted. Probe run in this round (a scratch Playwright script on harness.open_app with service_workers="allow", no repository change): the probe put a document titled PLANTED into a cache named `freelief-999.0.0`, which any page on the shared origin can do. It then navigated to `<app>/?v=999.0.0`, and the result was `title with ?v=999.0.0: PLANTED`, while `?v=abc` gave `Freelief`. test_offline.py `test_an_update_keeps_other_apps_caches_and_drops_only_old_freelief_ones` asserts that `freelief-9.9.9` is kept, so the suite encodes the keep-the-highest-name rule. Design section 9 bounds the accepted shared-origin risk: a sibling site 'can therefore replace a cached file ... until the next version replaces the cache'. Design Decision Log 2026-10-10 (UNT-126) introduced `?v=` and 'activation keeps the highest other version's cache' for AUD-057, and it does not mention that bound. (quoted in round UNT-139)
- Impact: The owner accepted the shared-origin risk (AUD-004) on a stated limit: a defect or compromise in a sibling site lasts only until Freelief's next version replaces the cache. The AUD-057 change removed that limit without saying so. One write to Cache Storage from any page on effigymedia.github.io (a sibling-site defect or compromise) leaves a cache that no Freelief update deletes. A link of the form effigymedia.github.io/freelief/?v=999.0.0 then shows that cache's page under Freelief's own address, offline, on every device that holds it. That page could show wrong crisis numbers to a person in crisis. The planted name also displaces the real previous-version cache that AUD-057 keeps, so the protection AUD-057 added is also lost. The precondition is a sibling-origin write, so the reach is contained. Medium.
- Direction: Make three changes in sw.js. (1) Honor `v` only when `event.request.destination === "script"` (never for a navigation) and only when it matches /^\d+\.\d+\.\d+$/. Otherwise answer from CACHE. (2) In activate, delete every freelief- cache whose suffix is not X.Y.Z. Keep the cache of the version this worker actually replaced, not the highest-sorting name: for example, record the outgoing version in a marker entry at install. (3) Add a test to test_offline.py: plant `freelief-999.0.0` holding a document, open `?v=999.0.0`, and assert the real app loads. After an update, assert that the planted cache is gone. In the same unit, state in design section 9 that the bound holds, and amend the UNT-126 Decision Log entry.
