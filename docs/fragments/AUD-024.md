### AUD-024 - The success criterion that crisis-line dates are no older than the release has no check and no release date to check against

- Severity: Medium
- Area: none - omission (crisis-line lifecycle)
- Evidence: Quoted in round UNT-010. Design section 2: "Every crisis line in the app has a last-checked date no older than the release that ships it." AGENTS.md Release: "re-check every crisis line and update its date". test_every_crisis_line_is_dated_and_dialable checks only the date format ("re.search(r\"Last checked \\d{4}-\\d{2}-\\d{2}\", ...)"). `git tag` prints nothing, so no release date is recorded in a form that a tool can read. tools/freelief.py has no release command. The directory entry also has "checked": "2026-10-07", and the release step does not name it. (quoted in round UNT-010)
- Impact: A release can ship a stale crisis line, and no command or gate fails. The criterion can only be met by memory.
- Direction: Add a release check (in build, or in a release step) that fails when any "checked" date in data/crisis-lines.json, including the directory entry, is older than the date of the release that ships it, or older than a window set in config. Name the directory entry in the release step.
- Effort: S
- Found by: the omission lens of round [[UNT-010]].
- **RULED 2026-10-08T12:53:29-04:00** — Fixed in UNT-074 as v0.6.9: build --release fails when a crisis line or the directory was checked more than crisis.maxCheckAgeDays (90, config.json) days ago, or has no valid date. A repo test checks the function with a far-future date. The AGENTS.md Release row names build --release, with an Instruction Changelog entry.
