### AUD-091 - Stage 8 says breathing loads at start and that ctx gives only read-only settings; the code loads the menu at start and hands the Visualizer a write callback

- Severity: Low
- Area: G. Documentation quality
- Evidence: Quoted in round UNT-082 at 82a1c6d. Design Stage 8, hard problem 3: "load only the shell, breathing and urgent help at start and every other screen on its first visit". The AUD-041 Decision Log entry says: "The launch target is met by loading only the shell, breathing and urgent help at start". app.js has `import * as menu from "./screens/menu.js"`, `menu: () => Promise.resolve(menu)` and `breathe: () => import("./exercises/breathe.js")`, and its comment says "The menu is the default and the first screen ..., so it loads with the shell." Stage 8 Contracts: "`ctx` gives ... the read-only setting values the screen needs (such as `rhythm` and `soundsOn`)". app.js also passes `calmMode: getSetting("calmMode"), saveCalmMode: (mode) => setSetting("calmMode", mode)` (AUD-066), and a grep finds no saveCalmMode in the design. The AUD-041 fix (UNT-079, v0.6.14) wrote the load sentence. (quoted in round UNT-082)
- Impact: The design is wrong about what is on the launch path, and REQ-026 and bench depend on that path. It also misses a write path in the screen contract. A reader who adds to the start-up set or the contract from Stage 8 works from false facts. This is the AUD-041 defect again: Stage 8 disagrees with the code.
- Direction: Amend AUD-041 (move it back to requested and append this attempt) instead of opening a new finding. Change Stage 8 and the AUD-041 Decision Log entry to say that the shell, the menu and urgent help load at start. Add saveCalmMode to the ctx contract as the one write path, given by the shell.
- Effort: S
