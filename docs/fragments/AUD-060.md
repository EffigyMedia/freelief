### AUD-060 - The worker reports whether the cache repair worked, but nothing listens, so a failed repair is invisible

- Severity: Low
- Area: C. Logging & diagnostics
- Evidence: Quoted in this round. sw.js: `const reply = (ok) => event.source && event.source.postMessage({ heal: ok }); ... .then(() => reply(true), () => reply(false))` with the comment 'The reply says whether it worked.' app.js healOfflineCache only does `registration.active.postMessage("heal")`; a search of app.js finds no `message` listener on navigator.serviceWorker. (quoted in round UNT-051)
- Impact: When the repair fails (a deploy window 404, a quota error), Freelief stays without offline use and nothing is logged. A field report 'it stopped working offline' cannot be traced to a failed repair.
- Direction: In app.js, listen for the `{ heal }` reply and `console.warn` a failure, or remove the reply and its comment so the code does not promise a signal that no one reads.
- Effort: S
- Found by: the operations lens of round [[UNT-051]].
- **RULED 2026-10-08T10:06:11-04:00** — Fixed in UNT-066 as v0.6.2: healOfflineCache() listens for the worker's reply and logs a failed repair with console.warn. Test: a source assertion, and a real launch with a working repair logs nothing. Technical reference updated.
