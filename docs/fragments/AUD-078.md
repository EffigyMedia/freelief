### AUD-078 - The Release row moves `live` (the deploy) right after the gate and before the tag exists, and puts shipped changes (the crisis-date update and the version bump) after GATE CLEAR

- Severity: Medium
- Area: H. Build & deployment readiness
- Evidence: AGENTS.md, trigger phrase Release (quoted in round UNT-082): 'Run audit rounds until `audit-gate.py` prints `GATE CLEAR`; then move `live` to the tag (`git push origin vX.Y.Z:live`); run the file audit; re-check every crisis line and update its date; purge `output/previews/`; run `bench`; run `build --release` (... a version bump after the last shipped change ...); verify `test` and `doctor` are green; bump the version; tag; push the commit and the tag.' The tag vX.Y.Z is made only at the 'tag' step, eight steps after it is pushed to live. Commands/audit-gate.py condition 5: 'no commit that touches a shipped file is later than the round unit's `created` stamp', and for a project every path outside docs counts as shipped (`return [".", ":(exclude)docs"]`). The crisis-date update (data/crisis-lines.json) and the bump (version.js) are commits to shipped files after GATE CLEAR. build --release runs before the bump and fails on them. Development_Process.md, Release step 1: 'no other release step starts before it prints GATE CLEAR'. Step 4 then puts 'verify test and doctor are green, bump ... tag, push' after validation. (quoted in round UNT-082)
- Impact: This hurts the 1.0 release and every release after it; the first 1.0 release cannot follow its own procedure. An agent that follows the row as written deploys first and validates afterwards. If it follows the row in order, `git push origin vX.Y.Z:live` fails because the tag does not exist yet, or it pushes an older tag. The crisis-line re-check and the version bump then change shipped files after the gate, so unaudited changes reach users through the gate that should stop them, and the clean round is stale. `build --release` runs before the bump and fails on 'changed after the last version bump'. Otherwise the session reorders the steps by hand, at the one moment the project calls a gate.
- Direction: Reorder the Release row. First re-check the crisis lines and update their dates, bump the version and commit. Then run the file audit, purge the previews, and run bench (release validation), build --release, test and doctor. Then run the release audit round to GATE CLEAR, tag that commit and push the commit and the tag. Move live last with `git push origin vX.Y.Z:live`. Say whether the tag commit may differ from the audited commit, and change audit-gate's rule or the row so that they agree. Delete the current sentence in the same edit, and log the change in docs/core/Instruction_Changelog.md.
