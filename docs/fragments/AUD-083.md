### AUD-083 - The Visualizer keeps every timer id for the whole session; the AUD-038 fix was not applied to activities/calm.js

- Severity: Low
- Area: D. Memory
- Evidence: activities/calm.js (quoted in round UNT-082): addShape() does `current.timers.push(setTimeout(() => group.remove(), settings.shapeLifeSeconds * 1000));` and `current.timers.push(setTimeout(addShape, settings.shapeEveryMs));`. The array is emptied only in stop(). config.json calm.shapeEveryMs = 2600, so it grows by about 2,770 dead ids an hour, and by about 1,385 an hour under the black screen, where addShape still reschedules. AUD-038 (built) fixed the same pattern only in breathe.js and bubbles.js: 'breathe.js resets run.timers at each phase ...; bubbles.js schedules through later(), which drops each id when it fires.' (quoted in round UNT-082)
- Impact: The Visualizer is the screen made for long sessions (music, black screen, the wake lock), so this growth is unbounded where sessions are longest. The memory used is small, and no person will see it at normal session lengths.
- Direction: Use the bubbles.js `later()` pattern in calm.js, so each id is dropped when its timer fires. Sweep the other activities for the same pattern (ripple.js pushes one id per tap and never drops it). Name the sweep in the unit close.
- Effort: S
- Found by: the operations lens of round [[UNT-082]].
