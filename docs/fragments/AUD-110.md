### AUD-110 - A stored setting has no end: the person cannot reset Settings, and choosing the default value again pins it

- Severity: Low
- Area: F. User experience
- Evidence: Quoted in round UNT-082. settings.js setSetting: `chosen[name] = value; localStorage.setItem(key, JSON.stringify(chosen))`. A value equal to the default is stored as a choice. F7: "Only a setting the person changes is stored, so a setting they never touched follows the default". screens/settings.js has no reset control. About says: "Clearing your browser data removes them." The origin is shared with three other sites, so clearing it also clears their data. (quoted in round UNT-082)
- Impact: A person who tries another rhythm and then goes back to the default is pinned to it, and a later change of default never reaches them. AUD-062 fixed this effect for people who never touched a setting. The only way to remove the data also deletes other apps' data.
- Direction: Store nothing for a value equal to the current default (delete the key), or add a "Use the defaults" control that clears Freelief's key only. Update About's wording to match.
- Effort: S
- Found by: the omission lens of round [[UNT-082]].
