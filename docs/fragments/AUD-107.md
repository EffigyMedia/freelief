### AUD-107 - With "Start breathing at once", an update found at launch reloads the page and restarts the breathing that is running

- Severity: Low
- Area: C. Edge cases
- Evidence: Quoted in round UNT-082. Decision Log: "Reloading only before the first touch never interrupts an exercise." app.js: `if (hadController && !interacted && !reloaded) { reloaded = true; location.reload(); }`, and `interacted` is set only by pointerdown or keydown. app.js routeName: `if (!name) return getSetting("openOn") === "breathe" ? "breathe" : DEFAULT_ROUTE;`. That means breathing runs with no touch. UNT-061 added openOn after the reload rule. No test covers the two together. (quoted in round UNT-082)
- Impact: A person who chose to open straight on breathing, online, after a new version is published, sees the guide reset a few seconds in. This is a small but sudden change, in the state the app exists to calm.
- Direction: Treat a running exercise as engaged. For example, do not reload when the first screen is breathe, and leave the new version for the next open. Correct the Decision Log sentence, and add a test with openOn set to breathe.
- Effort: S
- Found by: the omission lens of round [[UNT-082]].
