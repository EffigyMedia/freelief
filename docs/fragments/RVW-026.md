Offline copy and update (C):
- A failed install leaves no empty cache. sw.js precache(): `.catch((error) => caches.delete(CACHE).then(() => { throw error; }))`.
- A Cache Storage fault falls back to the network: `.catch(() => fetch(event.request)), // ... (AUD-059)`.
- The worker never fetches from another origin: `if (event.request.method !== "GET" || url.origin !== self.location.origin) return;`.
- Activation deletes only Freelief's own caches and keeps one other version. The other-version cache is chosen by `replaced` from `freelief~state`, so a rollback keeps the version it replaced.
- `files` agrees with sw.js: '32 shipped file(s), 235.9 KB; 31 cached.' and '[ OK ] the offline copy holds every shipped file'.
- doctor compares the FILES list with the disk.

Start-up failure (C):
- boot() failure puts the static fallback back: `if (staticFallback && !staticFallback.isConnected) document.body.replaceChildren(staticFallback); document.documentElement.dataset.ready = "fallback";`.
- A failed worker registration is logged and the app still runs: `console.error("Freelief could not install its offline copy:", error)`.
- A failed heal is logged: `console.warn("Freelief could not repair its offline copy.")`.

Settings storage (C):
- Every localStorage access in settings.js is in try/catch: getItem, setItem and removeItem are each wrapped.

Audio resources (C, D):
- When sound goes off, when help opens and when the app is hidden, the loops stop: `background.hold()`, and `audio.applySound(false)` then `background.restart()`, where rain() returns `{ stop: SILENT }` while `held`.
- The rain's thunder clears its timer and stops every rumble: `clearTimeout(thunderTimer); ... rolls.forEach((rumble) => rumble.stop(now + 2));`. Each rumble removes itself from the set on end: `rumble.onended = () => rolls.delete(rumble)`. So a long session does not accumulate thunder nodes.

About the relayed question on low thunder in the rain:
- Soft, distant thunder already ships, in v0.8.27 (RLG-063). It is in audio.js rain() and is tuned by config.json `sounds.rain.thunder`: `cutoffHz` 160, `level` 3.0, `firstAfterSeconds` 20, every 40 to 90 s.
- Its low-pass at 160 Hz puts nearly all of it below what most phone speakers reproduce. On a phone it may be inaudible. That is a question for the owner's phone check and the session that owns the request, not a defect of this lens.
