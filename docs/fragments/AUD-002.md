### AUD-002 - Boot has no failure path: one failed start-up fetch or module leaves a blank page with no breathing guide and no 'Need urgent help?' control

- Severity: High
- Area: C. Error handling
- Evidence: Quoted this round (UNT-010). index.html has an empty `<body>\n</body>` and no <noscript>. app.js: `async function boot() { const [loaded] = await Promise.all([loadConfig(), loadStrings("en"), loadCrisisLines()]); ... buildShell(); ...}` and the last line is `boot();` with no catch. loadConfig is `const response = await fetch("config.json"); return response.json();` with no `response.ok` check; strings.js and crisis.js are the same. app.js imports every module statically. Design section 8: "Any failure leaves the breath guide and the crisis lines usable." Design section 6: "Errors are calm and say what still works." Design section 9 names "the 'Need urgent help?' control on every screen" as a never-break item. Scratch probe (service workers blocked, one request aborted with internetdisconnected): config.json -> 'ready: None | body children: 0 | help control: 0 | guide: 0'; data/crisis-lines.json -> the same. No test covers a failed launch fetch (the only route() in the suite fakes data/standards.json). (quoted in round UNT-010)
- Impact: On a first visit over a weak mobile connection, in any deploy window where a data file 404s or returns HTML, when a parse error ships in a JSON file, when JavaScript is off, or on a browser that cannot parse one module, a person in a panic gets a blank screen with no message, no breathing guide and no crisis lines. The design promises the opposite. The impact is rare, but in the worst case it removes the safety route completely.
- Direction: Make boot fail soft. Check `response.ok`, catch per load, and fall back: build the shell and the breathing guide from defaults embedded in the page or app.js, and show the help dialog with the emergency-number line and the directory even when crisis-lines.json is missing. Put a static fallback in index.html that shows without JavaScript and that boot() replaces: one calm line, the instruction to call the local emergency number, and the directory link. Catch a boot() failure and show that fallback. Add a browser test that aborts each launch fetch in turn and asserts the guide (or the fallback), the help control and an emergency instruction are present.
