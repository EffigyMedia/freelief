### AUD-146 - A setting that a newer version retired is never removed: the rule that keeps unreadable stored settings keeps calmMode and natureSound forever, against the design's statement of what is stored

- Severity: Low
- Area: C. Edge cases
- Evidence: Quoted in this round and in round UNT-124. settings.js (AUD-121): "Stored values this version cannot read: a setting from a newer version, or a value it does not know. They are written back unchanged". initSettings has "else foreign[name] = value;", and save() writes "{ ...foreign, ...chosen }". calmMode and natureSound were stored under freelief.settings.v2 from v0.5.40 and v0.7.6 until v0.8.2 (git log -S on settings.js: 78af745, e4f2f93, d91aa61). Nothing tells a retired name from a newer version's name, so both are kept, and only Reset clears them ('foreign = {}'). Design section 8, Data and state: "holding only the values the person changed: the breathing rhythm, where it opens, how long the screen stays on, sound, vibration, the theme and the region for urgent help." Section 4: "What sound plays is not stored." UNT-108 entry: "`calmMode` and `natureSound` are no longer stored". About, privacy2, lists what is saved and names no sound choice. No rule names a retired key to drop. Confidence (whole-design lens): from a code read only. No test was run, and only a device that stored calmMode or natureSound before v0.8.2 is affected. (quoted in round UNT-124)
- Impact: A device that chose a Visualizer sound before v0.8.2 keeps that value, and every later save writes it again. The setting the owner retired then never leaves storage, against the privacy text's list of what is saved, and the design and About text are not quite true for that device. If a later version reuses either name with another meaning, it reads the stale value as a choice. The data is small, not sensitive and on the device, so the harm is low, but the design now has two rules that disagree and no way to retire a key.
- Direction: Add a list of retired setting names (calmMode, natureSound), for example in config.json as settings.retired, and have initSettings() drop those names instead of putting them in `foreign`. Keep the AUD-121 rule for other unknown keys. Add each name to the list in the unit that retires the setting. State the rule in design section 8 and in exercises_and_settings.md, and add a test that a stored retired name is gone after the next save.
- Effort: S
