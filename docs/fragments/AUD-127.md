### AUD-127 - RLG-033, the owner's check list, holds checks on Sort colors, which no longer exists, and its close rule gives it no exit

- Severity: Low
- Area: G. Process
- Evidence: Quoted in round UNT-104. RLG-033 Owed checks still list "Sort colors: drag a tile onto another tile and check that the two swap." and "Sort colors, manual screen-reader and keyboard check ... this check is still owed before 1.0." The record says: "Close it only when the owner reports each check." AGENTS.md says: "it closes only when the owner reports them all." A later note (2026-10-09, v0.7.8) says "The owed manual screen-reader and keyboard check moves from Sort colors to Unblock", but neither Sort colors line is struck or replaced. The drag-swap check has no successor at all. Design Decision Log: "Unblock replaces Sort colors ... REQ-014 is withdrawn". (quoted in round UNT-104)
- Impact: The owner cannot report a check on a screen that is gone, so under its own rule RLG-033 can never close. A session that prepares 1.0 from the list asks the owner to check something that does not exist, or it closes the record against its own rule. The same defect recurs whenever a screen with an owed check is removed.
- Direction: Append a dated note to RLG-033 that retires each Sort colors line by name and states its successor: Unblock's manual check, and Unblock's drag on a phone (already in the v0.7.8 note). Add a rule to the RLG-033 convention: when a screen is removed, its owed checks are retired or moved in the same unit.
