### AUD-123 - Tool thresholds and the performance baseline are in-code constants, and bench.py's BASELINE must be kept in step with baseline.md by hand

- Severity: Low
- Area: C. Regression risks
- Evidence: AGENTS.md Conventions: 'Every tunable lives in `config.json` with a committed default — never an in-code constant.' tools/bench.py: `RUNS = 7`, `CPU_SLOWDOWN = 4`, `BASELINE = {"launch_ms": 178, "response_ms": 74, "size_kb": 188.7}`, `TIMING_TOLERANCE = 0.25`, `BUSY_LOAD_PERCENT = 35`, with the comment 'Keep these in step with baseline.md when it is re-baselined'. baseline.md repeats 'If the busiest sample is over 35%' and the 178/74/188.7 figures. The rule's scope (the app or also the tools) is stated nowhere. fallback.js documents its own exception, and these do not. (quoted in round UNT-104)
- Impact: This hurts the next re-baseline, which is owed now. It must edit two files that nothing compares, and a missed edit makes bench flag against stale figures without a sign. The rule as written is not true of the tools, so a reader cannot tell whether that is allowed.
- Direction: Choose one rule. Either amend AGENTS.md to scope the rule to the shipped app and add an Instruction Changelog entry, or move the bench figures to one tool-side file. In both cases, make baseline.md or a test the single source of the baseline figures, so they cannot drift.
- Effort: S
