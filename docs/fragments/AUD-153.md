### AUD-153 - The Feedback message has no keep: leaving the page, as the checklist asks a volunteer to do, discards everything typed

- Severity: Low
- Area: F. User experience
- Evidence: Quoted in round UNT-124. screens/feedback.js: start() rebuilds the page with `container.innerHTML = ...` and fills the box with the template; `export function stop() {}` keeps nothing. app.js show() calls `current.stop()` and then `current.start(main, ...)` on every hash change. The checklist the box holds asks the volunteer to check '[ ] Breathing', '[ ] Pop Bubbles', '[ ] Zen Garden' ... '[ ] Settings', which means leaving Feedback and coming back. Other screens keep in-memory state for the visit without storage: unblock.js 'The board in use stays chosen while the app is open, so coming back continues it.' Design F9 lists the steps and the hidden-email edge, but says nothing about what happens to the message when the person leaves. (quoted in round UNT-124)
- Impact: A volunteer who fills in part of the check, goes to check the next screen and returns finds the template again, with no warning. The person most likely to do this is the one Freelief depends on for its 1.0 manual check, and the loss is silent.
- Direction: Keep the message text in a module-level variable in feedback.js for the life of the page (no storage, so the design's 'only Settings are stored' rule holds), and restore it in start() when it differs from the template. State this in F9. Add a test: type, go to #menu, return, and assert the text.
- Effort: S
