### AUD-156 - Settings says the offline copy is saved while the install is still running, and also after the install failed and the cache is empty (the AUD-112 fix does not work)

- Severity: High
- Area: C. Error handling; omission (unhandled states: install in progress, install failed)
- Evidence: Quoted in round UNT-139. screens/settings.js: "The offline copy is written all at once, so its cache exists only when every file is in it." and "Promise.resolve(self.caches?.has(`freelief-${self.FREELIEF_VERSION}`))" → 'settings.offlineReady' = 'This version is saved on this device and works with no internet.' sw.js precache() calls "caches.open(CACHE).then((cache) => cache.addAll(...))". caches.open creates the named cache at once, before addAll stores anything. The fetch handler also calls `caches.open(kept ? own : CACHE)` on every request. Probe (operations lens, Chrome 154, fresh throw-away context): `const y = await caches.open('probe-y'); await y.addAll(['version.js','no-such-file.js'])` returned `{'failed': True, 'has': True, 'n': 0}`, so a failed addAll leaves an empty cache that `caches.has` reports as present. Probe (omission lens, scratch Playwright script with Chrome against a local server, nothing in the repo changed). Case 1: icons/icon-512.png delayed 6 s. For 5 s the result was {'has': True, 'n': 0, 'line': 'This version is saved on this device and works with no internet.', 'st': ['installing', None, None]}. Case 2: icons/icon-512.png answers 404, so the install fails. The registration was gone (st None), and for all 8 s the result was {'has': True, 'n': 0, 'line': 'This version is saved on this device and works with no internet.'}. test_settings_says_whether_this_version_is_ready_offline checks only the happy path and the blocked worker, and test_slice2.py waits on the same false signal: "wait_until(page, \"caches.has('freelief-' + self.FREELIEF_VERSION)\", 8000)". (quoted in round UNT-139)
- Impact: AUD-112 added this line for a person who installs Freelief to have it ready for a future crisis. In both states (install running, install failed) the line says the opposite of the truth. On a slow first visit, or when the network drops during the install, the person reads 'works with no internet', goes offline, and at the next attack the app does not open. The empty cache stays until a later install succeeds, so the false line lasts too. The indicator exists for exactly this case, and it fails open.
- Direction: Reopen AUD-112 and append this attempt; do not raise a second defect. Make the check prove the content, not the cache name: report ready only when the cache holds every file in FILES (compare the cache keys with the list, or have the worker report its state - installing, active, failed - through a message, or at minimum `cache.match` the required files index.html, app.js, version.js, strings/en.json, data/crisis-lines.json). Show a third text while the install runs. In precache, delete the version's cache when addAll fails, so a failed install leaves no empty cache. Delete the false comment in the same edit. Make the test wait for the worker to be active and assert the key count, and add a failed-install case (one listed file missing or 404) that expects 'settings.offlineNotReady'.
