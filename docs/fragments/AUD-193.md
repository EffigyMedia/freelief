### AUD-193 - The emergency numbers, the first thing the help dialog asks a person to tap, have no source and no last-checked date, so the release re-check never covers them

- Severity: Low
- Area: none - omission (a safety-critical object with no check, no source and no date)
- Evidence: data/crisis-lines.json gives each region only '"emergency": "911"' (US, CA), '"999"' (GB), '"112 or 999"' (IE) and '"000"' (AU), with no source or checked field. Each line has both, for example '"source": "https://988lifeline.org/", "checked": "2026-10-07"'. tools/freelief.py stale_crisis_checks() reads only 'entries = [("directory", ...)]' and '(f"{code}: {line['name']}", line.get("checked")) for line in region["lines"]'. AGENTS.md Release row: 're-check every crisis line and update its date'. app.js renders the emergency numbers first, as 'button primary emergency-call' tel: links. (quoted in round UNT-155) (quoted in round UNT-155)
- Impact: The most prominent number in the dialog is the only crisis number with no record of where it came from or when it was last checked, and build --release does not ask for one. Emergency numbers rarely change, so the risk is low. But the rule that 'Crisis-line data is safety-critical' does not reach the number that a person in immediate danger calls first.
- Direction: Add 'emergencySource' and 'emergencyChecked' to each region. Make stale_crisis_checks include them, and state the field in the Release row and in design section 9. Record the source for the five current numbers in the session that adds the fields.
- Effort: S
- Found by: the omission lens of round [[UNT-155]].
