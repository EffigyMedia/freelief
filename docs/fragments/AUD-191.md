### AUD-191 - Update now continues after the person leaves Settings, and then reloads the page under another screen, including an open urgent-help dialog

- Severity: Medium
- Area: none - omission (a verb whose state has no exit when its screen ends)
- Evidence: screens/settings.js: 'export function stop() {}'. updateNow() ends with 'if (settled === true) location.reload();' and 'if (refreshed === true) location.reload();'. Each wait can last up to config settings.updateWaitSeconds (60). app.js show() calls 'if (current) current.stop();' when the screen changes, and nothing else cancels the update. sw.js states the rule: 'A version never changes under a page the person is using (AUD-057).' The help dialog is open on every screen, and a reload closes it. (quoted in round UNT-155) (quoted in round UNT-155)
- Impact: A person presses Update now on a slow network, then goes to Breathe or presses 'Need urgent help?'. When the update ends, Freelief restarts without warning. The breath they follow starts again, or the crisis-line dialog they are reading closes. The sequence is rare. When it happens, it breaks a never-break path at the worst moment, and nothing shows why.
- Direction: In stop(), mark the pending update as abandoned (an AbortController or a flag), and make updateNow reload only while Settings is still the shown screen and the help dialog is closed. Otherwise, let the new version take over at the next open, as app.js does after the first touch. Add a test: start Update now with a worker that answers late, go to #breathe, and assert that no reload occurs.
- Effort: S
