### AUD-056 - 'Update now' deletes the offline copy and the worker before it knows the network works, so on a dead or captive connection the app is gone until the device is online again

- Severity: Medium
- Area: C. Edge cases (interruption mid-operation)
- Evidence: Quoted in this round. screens/settings.js updateNow: `if (!navigator.onLine) { ... return; } ... const keys = await caches.keys(); await Promise.all(keys.filter((key) => key.startsWith("freelief-")).map((key) => caches.delete(key))); const registration = await navigator.serviceWorker?.getRegistration(); if (registration) await registration.unregister(); } finally { location.reload(); }`. navigator.onLine is true on Wi-Fi with no internet behind it, behind a captive portal, or on a failing link. Scratch probe (operations lens) with the project harness: install, then abort every request while the browser still reports online (`before: ['freelief-0.5.36'] True`), click .update-now, then go offline and reload -> 'offline reload: Page.reload: net::ERR_INTERNET_DISCONNECTED'. The only test, test_settings_shows_the_version_and_update_now_refreshes_only_freelief, runs the update with a working network. The hint says only "Gets the newest version from the internet and restarts Freelief. Your settings are kept." The Decision Log entry for Update now names no failure state. The design names offline use as a never-break item. (quoted in round UNT-051)
- Impact: A person who taps Update now on a captive portal, a weak signal or a link that drops mid-update loses the installed app. Until real internet returns, every launch shows the browser's error page: no breathing guide and no 'Need urgent help?' control. The next time they open Freelief offline, possibly in a panic attack, it does not open. This breaks offline use (REQ-008) through the app's own control, and it needs only one tap at the wrong moment.
- Direction: Do not delete the working copy first. Call `registration.update()`, wait for a new worker to reach `installed` in its own versioned cache (or report that the version is already current), and only then let it take over and reload; the new worker's activate already deletes the old freelief- cache. Alternatively, confirm that a no-store fetch of version.js succeeds before deleting anything. If the update or the precache fails, keep the current cache and worker and show a calm 'Could not update; this version still works offline' line from strings. Add a test that aborts the network while navigator.onLine stays true, presses Update now, and then expects an offline reload to show the menu and the help control.
- Effort: S
