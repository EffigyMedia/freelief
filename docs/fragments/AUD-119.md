### AUD-119 - doctor crashes with a traceback, and prints no summary, when config.json is malformed or crisis-lines.json is missing

- Severity: Low
- Area: C. Error handling
- Evidence: tools/freelief.py cmd_doctor checks each shipped JSON file and records a failure ('config.json parses'). It then runs `config = json.loads((ROOT / "config.json").read_text("utf-8"))` and `stale_crisis_checks(window)` with no guard. stale_crisis_checks reads data/crisis-lines.json and indexes `data["directory"]` and `region["lines"]`. Round UNT-104 ran doctor on a `git archive HEAD` copy with config.json set to `{ broken`. The output ended in `json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes` with exit 1. It printed no 'NOT READY' line and no fix. AGENTS.md says doctor verifies 'that every shipped JSON file exists and parses'. (quoted in round UNT-104)
- Impact: This hurts a maintainer at Resume after a bad edit to config.json or the crisis data, which is exactly the fault doctor exists to report. The run still fails closed, but the report becomes a stack trace, not the actionable line that doctor is designed to print.
- Direction: Skip the crisis-age and standards warnings when config.json or the crisis data did not parse, and print why. Alternatively, wrap them so that a failure becomes a check() line. Add a test that runs doctor with a broken config.json and asserts 'NOT READY' and exit 1.
- Effort: S
