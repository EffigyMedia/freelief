### AUD-062 - Settings saves every default as if the person chose it, so the new long out-breath default never reaches anyone who changed any setting while box breathing was the default

- Severity: Medium
- Area: none - omission (Settings object: create and end)
- Evidence: Quoted in round UNT-051. settings.js setSetting writes the whole object: `values[name] = value; ... localStorage.setItem(key, JSON.stringify(values));`, and `values = { ...defaults }` holds every default. test_slice2 asserts the stored object after only rhythm, theme, sounds, region and haptics change: `{"rhythm": "slow", "sounds": False, "theme": "light", "calmMode": "music", ...}`. calmMode "music" is stored although the test never chose it. Box was the default from v0.5.18 (1918fb3) to v0.5.35. origin/live is f90a4ce (v0.5.34), a box-default build. REQ-023 and the Decision Log say "A saved rhythm is kept". The same file already solved this for one key: "Sounds are a new key (2026-10-07): an old stored `tones: false` was never a choice ... so it does not carry over." No such guard exists for the rhythm. Settings has no reset-to-defaults control. (quoted in round UNT-051)
- Impact: This bears directly on the owner's question of whether the long out-breath is better than box. Any person who changed any setting on a v0.5.18 to v0.5.35 build, such as the region, sounds, vibration, theme or Visualizer sound, has `rhythm: "box"` saved as if chosen, and keeps box breathing after v0.5.36. The owner's phone is likely one of these devices, so a phone check of v0.5.36 can show box and suggest the change did not land. Every later change to a default (sounds, haptics, theme) has the same blind spot.
- Direction: Store only the keys the person changed: write a key only in setSetting, and never write the defaults. For the box era, decide with the owner whether a stored `rhythm: "box"` saved under the v1 key is migrated. One way is to bump the storage key to v2 and carry over only values that differ from the default of the version that saved them. State in design F7 what 'a saved rhythm is kept' means. Add a test that changing one setting stores only that key, and a test that a stored box from the box era behaves as the owner decides.
- Effort: S
- Found by: the omission lens of round [[UNT-051]].
- **RULED 2026-10-08T01:53:29-04:00** — Fixed in UNT-055 as v0.5.40. settings.js keeps a chosen map and writes only it, under freelief.settings.v2 (config settings.storageKey). The v1 store (settings.legacyStorageKey) is read once, carried over only for values that differ from today's default, with a stored box rhythm dropped, and removed. Design F7 states what 'a saved rhythm is kept' means; the Decision Log records the migration rule (implementer's choice, stated to the owner). Tests: one change stores one key; a v1 store with box and five other values keeps only theme dark and haptics off, removes v1, and shows the default rhythm; the round trip stores only the five changed keys. Mutation check: writing every value makes two tests fail. 120 tests.
