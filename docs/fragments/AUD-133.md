### AUD-133 - Update now with no new version deletes the offline copy before the fresh copy is stored; one failed file leaves no offline copy and no message

- Severity: Medium
- Area: C. Error handling
- Evidence: Quoted in this round. screens/settings.js updateNow(), when registration.update() finds no new worker: 'const keys = await caches.keys(); await Promise.all(keys.filter((key) => key.startsWith("freelief-")).map((key) => caches.delete(key))); await registration.unregister(); } finally { location.reload(); }'. Its comment says: 'Nothing is removed until the network is shown to work (AUD-056)'. sw.js precache uses 'cache.addAll(...)', which fails as a whole if any one file fails. A scratchpad probe on a temporary copy installed v0.8.14 on #settings, removed icons/icon-512.png from the server, and pressed Update now. After the reload it printed 'controller: False', 'status text: ''' and, offline, 'offline: app does not start: Page.reload: net::ERR_INTERNET_DISCONNECTED'. test_settings_shows_the_version_and_update_now_refreshes_only_freelief tests only the success path. (quoted in round UNT-124)
- Impact: The person pressed Update now to make the app work better. If one file fails to download, for example during a flaky mobile connection or a GitHub Pages deploy that is half-done, the working offline copy is gone, nothing says so, and the next offline open in a crisis shows the browser's offline error page. The copy comes back only at the next online launch that installs it successfully.
- Direction: Do not delete before the replacement is proven. Fetch every file in FILES into a temporary cache first ('freelief-<version>-refresh'), and swap it in only when all of them arrived. Otherwise keep the current copy and show 'settings.updateFailed'. Unregister only after the swap, or not at all, because the same version needs no new registration. Add a test with one failing file that asserts the offline copy survives and the failure message shows.
- Effort: M
- Found by: the operations lens of round [[UNT-124]].
- **RULED 2026-10-10T13:19:49-04:00** — 2026-10-10 (UNT-127, v0.8.17): fixed as the Direction said. sw.js handles 'refresh': it fetches every FILES entry with cache 'reload' into freelief~refresh-<version> (a name that does not start with PREFIX), copies the entries over this version's cache only when addAll succeeded, deletes the temporary cache and replies { refresh }. settings.js posts 'refresh' instead of deleting caches and unregistering; on false it shows settings.updateFailed. test_update_now_with_one_failed_file_keeps_the_offline_copy_and_says_so removes icon-512.png from the server, presses Update now, and asserts the message, the same number of cached files, a live controller and an offline start; it fails against the old code. 193 tests pass.
