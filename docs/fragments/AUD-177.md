### AUD-177 - The install instructions that docs/README.md promises for 1.0 have no record, and nothing says what an iPhone home-screen copy needs

- Severity: Low
- Area: none - omission (a promised step with no owner, record or release criterion)
- Evidence: Quoted in round UNT-139. docs/README.md: "Version 1.0 will be the first release, after a full release audit; this page will then say how to install it." REQ-008: "installs to the home screen". Design section 10, 'Release criteria for 1.0', does not list the install text. No RLG or REQ record names it (a grep for 'how to install', 'add to home' and 'home screen' over the fragments finds only REQ-008, AUD-003 and AUD-012). The app has no install flow and no install text in strings/en.json. Unconfirmed, with medium confidence: on iPhone, a web app added to the home screen keeps storage apart from Safari's. Then the Safari offline copy and settings may not carry over, and the home-screen copy fills only when it is first opened online. No design clause, test or RLG-033 check covers this. (quoted in round UNT-139)
- Impact: At 1.0 the public page would still say that it 'will' explain installing, or the step is written in a hurry. An iPhone user has no install prompt and must find Add to Home Screen in the Share menu. If the storage split is real, such a person may be told in Safari that the copy is saved, and then find that the home-screen copy does not open offline.
- Direction: Track the install text as an RLG item and add it to the 1.0 release criteria. Check on an iPhone whether the home-screen copy shares Safari's cache. If it does not, say in the install text to open Freelief once from the home screen while online. Add that check to RLG-033.
- Effort: S
