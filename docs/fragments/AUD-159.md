### AUD-159 - A release has no exit when bench is busy: nothing requires a valid run, and no run has been valid under the current rule since v0.7.13

- Severity: Medium
- Area: none - omission (a state with no exit in the Release procedure)
- Evidence: Quoted in round UNT-139. AGENTS.md Release row: "run `bench` on a quiet machine (exit 2 means busy, not valid)". The row does not say what happens after exit 2: wait and rerun, a waiver, or stop. `build --release` checks the size, a clean tree, the version bump and crisis freshness, and not bench. A grep finds no 'bench' in Commands/audit-gate.py. docs/performance/log.md: the last valid entry is "Slice 8 close and re-baseline (v0.7.13)". Since then: v0.8.15 "NOT VALID: busy machine", v0.8.22 "NOT VALID: busy machine" (load 63.9%), and v0.8.14's four runs "Under the rule of AUD-134 ... none of the four would be comparable", which also measured REQ-027 as FAIL. The health step got two more exit-2 runs (48.3%, 38.5%), each with a launch FLAG of +37-38%. RLG-033 has held "run ... bench on a quiet machine ... and re-baseline" as owed since 2026-10-09. The live preview was moved with only invalid runs. (quoted in round UNT-139)
- Impact: REQ-026 and REQ-027 are Must targets. REQ-027 was last measured validly as failing, and its fix has only busy-machine evidence. A launch FLAG is open and unconfirmed. A release can pass every tool check and the gate with no valid performance evidence. The rule that a run is valid only within 5 points of a 27% baseline load cannot be met on this machine as it is used, and nothing says what to do then.
- Direction: Write the exit into the Release row and the design (section 9): a release needs one valid run of the release commit, recorded in the log; on exit 2, close other programs and run it again; if no valid run is possible, the owner rules for that release, by name. Make `build --release` check, or have audit-gate.py print, that log.md has a valid entry for the version being released. Re-baseline on a quiet machine as RLG-033 owes.
