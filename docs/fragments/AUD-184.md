### AUD-184 - test_reduced_motion_keeps_the_guide_still is flaky: it compares two reads around a fixed 300 ms wait, but the guide moves once from the start scale to the still scale after two frames

- Severity: Medium
- Area: H. Test coverage
- Evidence: Round UNT-155. Health step: the full `python tools/freelief.py test` failed with '[FAIL] test_app.py::test_reduced_motion_keeps_the_guide_still: the guide moved under reduced motion' (exit 1, 218 passed). `test test_app` passed twice alone. The test: `page.wait_for_timeout(300)`, then `first = ...getComputedStyle(e).transform`, then `page.wait_for_timeout(1500)`, then `later = ...`. exercises/breathe.js start() sets `circle.style.transform = `scale(${breathing.guideMinScale})`` and then `run.frame = requestAnimationFrame(() => { run.frame = requestAnimationFrame(runPhase); });`. Under reduced motion runPhase sets `scale(${breathing.guideStillScale})`. config.json: 'guideMinScale': 0.55, 'guideStillScale': 0.8. If the two frames have not run 300 ms after ready, as on a loaded run, the first read is 0.55 and the second is 0.8. The cause is likely this race; this round did not reproduce it. (quoted in round UNT-155)
- Impact: This test guards REQ-010, reduced motion. A suite that goes red at random makes 'verify test is green' in the Release row a matter of luck, and trains sessions to rerun until green. A rerun habit then hides a real reduced-motion regression. The app itself is not shown to be wrong: the step from 0.55 to 0.8 has no transition.
- Direction: Before the first read, wait for the first phase to have run, for example `wait_until(page, "document.querySelector('.phase').textContent !== ''")`. Or set the still scale in start() under reduced motion, so the circle never changes size. Then run the full suite several times to show the test is stable.
- Effort: S
