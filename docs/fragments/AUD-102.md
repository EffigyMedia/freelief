### AUD-102 - The procedure that records a verified standard can never show one: adding the entry needs a version bump, and the page shows an entry only for the running version

- Severity: Medium
- Area: A. Correctness & compliance
- Evidence: Quoted in round UNT-082. trust_pages.md step 3: the entry is added "with `version` (the checked version) ... in its own unit with the version bump". screens/standards.js: `standards.verified.filter((s) => s.version === self.FREELIEF_VERSION)`. data/standards.json is shipped: it is not in NOT_SHIPPED, and sw.js FILES lists "data/standards.json". test_repo.py test_every_committed_shipped_change_came_with_a_version_bump fails a shipped change that has no bump. So an entry for checked version X ships in version X+1, and the filter then hides it. An entry with version X+1 would claim a check that nobody did, and REQ-029 forbids that. The only test, test_a_verified_standard_is_listed_with_date_and_tester, uses an entry for the running version, so it cannot see the dead end. (quoted in round UNT-082)
- Impact: REQ-029 and REQ-020 cannot be met. A volunteer's manual check never becomes a claim, so the owner's selling point ("The owner wants the standards used as a selling point") cannot happen. The first attempt will be stuck, or will be pushed into a false claim to get it shown.
- Direction: Decide what a check covers. One way: the entry names the checked version, and the page shows it while the running version differs from the checked one only by changes that do not touch what was checked, such as the standards file itself. Another way: record the entry in the same commit as the version it checks, before the bump. Write the rule in trust_pages.md and the design. Add a test that walks the real procedure: add the entry, bump, and see that it shows.
- Effort: M
- Found by: the omission lens of round [[UNT-082]].
- **RULED 2026-10-09T08:46:05-04:00** — 2026-10-09, owner ruling by the question tool: an entry names the version checked, and it shows in later versions until a release changes a screen, the styles, the text or the shell; a test checks this. A release that changes the interface drops the claim until people check again. (Not chosen: record the entry in the same commit as the checked version.)
