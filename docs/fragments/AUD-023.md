### AUD-023 - A recorded standard has no version, so a claim outlives the version it was checked for

- Severity: Medium
- Area: none - omission (end of the Standard object)
- Evidence: Quoted in round UNT-010. REQ-029: "...recorded, with its date and tester, for the version shown." Design section 4 says a Standard "has a level, a check date, and the tester of the manual check" and gives it no version. screens/standards.js renders "t(\"standards.verifiedItem\", { name: s.name, level: s.level, date: s.checked, tester: s.tester })" with no version. The string says "Each one was checked by people, with a screen reader and with a keyboard only, for this version:". test_a_verified_standard_is_listed_with_date_and_tester uses a fake entry with no version field. (quoted in round UNT-010)
- Impact: After the first volunteer check is recorded, the next patch release shows the standard as met "for this version" when nobody checked that version. This is the overclaim that principle 4 and REQ-029 forbid. Today it is latent only because "verified" is empty.
- Direction: Add a "version" field to each entry in data/standards.json. Show an entry only when it equals self.FREELIEF_VERSION, or define in the design which changes keep a check valid. Add the field to design section 4. Add a test that an entry for a different version is not shown.
- Effort: S
- Found by: the omission lens of round [[UNT-010]].
- **RULED 2026-10-08T13:06:36-04:00** — Fixed in UNT-076 as v0.6.11: standards.js shows only entries whose version equals FREELIEF_VERSION; standards.json's rule names the fields. The test shows only the current-version entry, and the 'none' text when only an older version's entry exists.
