### AUD-039 - User-facing text outside the strings file breaks REQ-017

- Severity: Low
- Area: B. Architecture quality
- Evidence: Quoted in round UNT-010. REQ-017 (must): "All user-facing text lives in one strings file per language, so a translation can be added without a code change." screens/feedback.js: `return platform ? \`${platform}${mobile ? " (phone or tablet)" : ""}\` : null;`. That literal appears in the feedback text the person reads. data/crisis-lines.json holds English display text: "country": "United States", "hours": "24/7, free and confidential", and the directory "note". AGENTS.md: "`strings.js` + `strings/en.json` — **the single source of all user-facing text.**" (quoted in round UNT-010)
- Impact: A translation needs a code change in feedback.js and an edit to the safety-critical crisis data file. The single-source rule is false as written.
- Direction: Move " (phone or tablet)" into strings/en.json. Either key the crisis-line display text by string ids, or record a Decision Log amendment that crisis data carries its own text, and update REQ-017's history.
