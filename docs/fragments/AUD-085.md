### AUD-085 - A failed service-worker registration is swallowed with no log, so the loss of offline support is invisible

- Severity: Low
- Area: C. Error handling
- Evidence: app.js (quoted in round UNT-082): `navigator.serviceWorker.register("sw.js", { updateViaCache: "none" }).then(...).catch(() => { // Offline support is lost, but the app still works online. });`. The same catch also swallows any error from healOfflineCache(). No console call and no visible state is set. (quoted in round UNT-082)
- Impact: This hurts a person whose browser refuses the worker (a private mode, a policy, a broken sw.js in a deploy). They believe the app works offline, as the README and REQ-008 say, and find out only when they are offline in a crisis. A field report 'it does not work offline' cannot be debugged from the console.
- Direction: Log the error with `console.error("Freelief could not install its offline copy:", error)`. Consider a quiet 'offline copy not available' line on About, which already shows the version. Keep the app usable online, as it is now.
- Effort: S
