### AUD-154 - The Feedback flow has no offline state: 'Open on GitHub' does not say it needs an internet connection

- Severity: Low
- Area: A. Correctness & compliance
- Evidence: Quoted in round UNT-124. Design F6 states the offline case for help: 'the directory link and any web chat say they need a network', and the strings carry it ('help.directoryNote': '{note} This link needs an internet connection.', 'help.chatNote'). Design F9 lists no offline state. strings/en.json feedback.githubNote: 'Opens a new issue on GitHub. Paste your message there. GitHub issues are public ... GitHub needs a free account.' It says nothing about a network. The design's checklist says '[x] Every flow in Stage 5 has its edge cases and failure states specified.' The tone rule (section 6): 'Errors are calm and say what still works.' (quoted in round UNT-124)
- Impact: Freelief is meant to be used offline. A person who writes feedback with no connection presses Open on GitHub and gets the browser's error page in a new tab, with nothing in Freelief that said it would. The message is not lost if they pressed Copy first, so the harm is small.
- Direction: Add the offline state to F9 and append 'It needs an internet connection.' to feedback.githubNote, as help.directoryNote does. Optionally show the same line in the copy status when navigator.onLine is false.
- Effort: S
- Found by: the omission lens of round [[UNT-124]].
