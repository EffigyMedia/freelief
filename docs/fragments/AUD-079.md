### AUD-079 - bench's REQ-027 verdict flips between pass and fail with machine load, so it cannot tell a regression from a busy machine

- Severity: Medium
- Area: D. Performance
- Evidence: Round UNT-082 health check, same machine, same day: `python tools/freelief.py bench` exited 1 three times with response medians of 158.5 / 163.7 / 167.2 ms, and 229.5 ms on a clean worktree of 82a1c6d. The control at 6d3ba6b (v0.6.3), the commit that recorded the 74 ms baseline, measured 168.6 ms FAIL. CPU LoadPercentage was 60. My own runs in this review, with LoadPercentage 54, exited 0: response 81.5, 83.2, 73.4 and 81.9 ms, with worst runs of 102.7, 86.5 and 96 ms. docs/performance/baseline.md, Environment, names the CPU, OS, Chrome and throttle but not a quiet machine. It says 'The tolerance is wide because a millisecond-scale figure moves with machine load. The targets are hard limits whatever the tolerance says.' Performance_Testing.md section 2 says: 'Fix the conditions. Same machine class, same build configuration, quiet system.' and 'a metric noisier than the regression tolerance can't enforce that tolerance.' bench.py takes `statistics.median` of `RUNS = 7` and does not record or check load. (quoted in round UNT-082)
- Impact: The Release row and the slice definition of done run bench as evidence for REQ-027 (a visible response within 100 ms on the urgent-help control). The same code gives 73 ms or 229 ms, so the exit code depends on what else runs on the machine. A real regression on the urgent-help path can pass on a quiet run, and a clean build can fail on a busy one. That pushes people to rerun until the result is green, and a release validation run (Performance_Testing.md section 8) cannot be trusted.
- Direction: Make the bench result reproducible. Measure main-thread work from a CDP trace (task durations) and not only wall-clock time. Or sample CPU load before and after each run and refuse or mark the run 'busy machine, not valid' above a stated threshold. Record the spread (median, worst, run-to-run variance) in baseline.md, and state the 'quiet machine' condition in its Environment section. Rerun the baseline under that condition, and log the slice 7 checkpoint against it.
