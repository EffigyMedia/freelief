### AUD-005 - The router accepts inherited object names from the URL hash, so a link such as #constructor gives a blank app and a stuck router

- Severity: Medium
- Area: E. Security
- Evidence: app.js: `function routeName() { const name = location.hash.replace(/^#/, ""); return name in ROUTES ? name : DEFAULT_ROUTE; }`. ROUTES is a plain object literal, so `"constructor" in ROUTES`, `"__proto__" in ROUTES` and `"toString" in ROUTES` are true. Probe (scratch script, harness server): a cold open at `#constructor`, `#__proto__` or `#toString` gave `ready= None main children= 0 errors= ['current.start is not a function']`. In a running app, setting `#constructor` and then `#menu` left `screen= constructor shown= None`, with errors `'current.start is not a function', 'current.stop is not a function'`. Every later hash change throws at `current.stop()`, so the router stays dead until a reload. buildShell runs before show, so the header still exists, but the breathing guide never starts. (quoted in round UNT-010)
- Impact: The URL hash is input that anyone controls. A shared or mistyped link opens Freelief with no breathing guide. This breaks REQ-018 (the guide at launch with no question), and nothing on screen tells the person how to recover. The person affected is someone in a panic attack.
- Direction: Use `Object.hasOwn(ROUTES, name)`, or build ROUTES with `Object.assign(Object.create(null), {...})` or as a Map. Add a test that opens `#constructor`, `#__proto__` and `#toString` and asserts that the breathing screen shows, and that a later `#menu` works.
- Effort: S
