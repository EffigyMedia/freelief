### AUD-179 - Update now can stay at 'Updating' with the button disabled, because nothing ends the wait if the worker never answers

- Severity: Low
- Area: none - omission (a state with no exit)
- Evidence: Quoted in round UNT-139. screens/settings.js sets status "settings.updating" ("Updating. Freelief will restart in a moment.") and aria-disabled. It then awaits a Promise that resolves only on a worker message with a boolean 'refresh', or on the incoming worker reaching 'activated' or 'redundant'. There is no timeout. sw.js sends the 'refresh' reply only at the end of a waitUntil chain that fetches all 32 files with cache: "reload". A browser may stop a worker whose event runs too long, and then no message is sent. The button is enabled again only in the finally block, after that await. (quoted in round UNT-139)
- Impact: On a slow or stalled connection the person sees 'Freelief will restart in a moment' with no end. Pressing again does nothing until they leave Settings. They cannot tell whether the current copy still works. It does still work, but the screen does not say so.
- Direction: End the wait after a time from config.json (for example 60 s). Then show "settings.updateFailed" ("Could not update. This version still works offline.") and enable the button again. Remove the message listeners when the wait ends.
- Effort: S
- Found by: the omission lens of round [[UNT-139]].
