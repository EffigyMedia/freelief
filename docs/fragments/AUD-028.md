### AUD-028 - No supported-browser baseline is stated, and the suite runs only in Chromium for a phone-first app

- Severity: Medium
- Area: none - omission (unstated target)
- Evidence: Quoted in round UNT-010. harness.py: "_browser = _playwright.chromium.launch(channel=\"chrome\")" with "_playwright.chromium.launch()" as the fallback. No test uses WebKit or Firefox. The design names "phone first" (section 7, row 1) and lists no browser or version. The code depends on dialog.showModal(), Intl.Locale, ES modules, optional chaining ("navigator.userAgentData?.brands") and "??". Because app.js imports every module statically, one module that an older browser cannot parse stops the whole app. (quoted in round UNT-010)
- Impact: iPhone users (all WebKit) and Firefox users get no automated check. A defect on Safari in the help dialog, the service worker or the layout reaches a person in crisis, and nothing finds it before the owner's own phone.
- Direction: State the supported browsers and the oldest versions in design section 7. Run the suite (or at least the never-break tests: launch, help, offline, keyboard) in Playwright WebKit and Firefox as well. Note the result in doctor.
- Effort: M
- Found by: the omission lens of round [[UNT-010]].
