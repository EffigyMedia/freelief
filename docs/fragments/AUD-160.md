### AUD-160 - Fixing units set findings to built themselves, so no round confirms a fix before the finding leaves the work queue

- Severity: Medium
- Area: G. Process amendments
- Evidence: Quoted in round UNT-139. Audit_and_Testing.md section 9: '`requested` when raised; `in-flight` while a unit works on it; `built` when a later round confirms the fix.' Commands/audit-round.py: 'A finding every lens that re-checked it reports `done` becomes `built`'. In practice, 29 findings of round UNT-124 (AUD-125 to AUD-155, except AUD-028 and the declined AUD-132) are status 'built', and each has only a fixer's ruling, for example AUD-138: '**RULED 2026-10-10T13:41:02-04:00** — 2026-10-10 (UNT-130, v0.8.19): fixed.' None has a 'Re-checked ... by round' line. THR-001: 'every finding of round UNT-124 is built except AUD-028'. The brief of this confirming round asks only for 'Every AUD- fragment ... with status requested or in-flight'. No Instruction Changelog entry documents the deviation. A grep of the log for 'built' finds only the 2026-10-07 repository entry. This round found AUD-123, which a fixer marked built, only partly done. (quoted in round UNT-139)
- Impact: The confirming re-check, which section 5 calls 'where most of a round's value is', is skipped for every fix that its fixer marks built. The release gate checks that no finding is requested or in-flight, so it can pass with fixes that no round has confirmed. A round whose brief follows the statuses sees only AUD-028. This round looked at the built fixes only because it read past its brief.
- Direction: Have a fixing unit set its finding to in-flight with its ruling, and leave the move to built to `audit-round.py record --apply-rechecks`. Alternatively, record an owner amendment in the Instruction Changelog that permits this and makes every round re-check the findings built since the last round. Then move the findings of round UNT-124 that this round confirmed, and put AUD-123 back to requested.
