### AUD-158 - No valid benchmark since v0.7.13: the urgent-help fix (AUD-131) and a persistent launch FLAG of +34% to +66% have no valid run behind them

- Severity: Medium
- Area: D. Performance
- Evidence: Quoted in round UNT-139. docs/performance/log.md: every entry after 'Slice 8 close and re-baseline (v0.7.13)' is invalid or over the limit. v0.8.14: 'Under the rule of AUD-134 ... none of the four would be comparable', launch +34% to +38%, response 'FAIL (AUD-131)'. v0.8.15: 'NOT VALID: busy machine', 81% to 96.5% load. v0.8.22 live move: 'NOT VALID: busy machine', launch '256.2 ms | +66% | FLAG', with the note 'The launch FLAG is load'. This round's health step had two runs that exited 2 [BUSY] at 48.3% and 38.5% against a limit of 32%, with launch 211-212 ms (+37-38%). AGENTS.md accepts an invalid run at a live move: 'records the run ... valid or not, so a regression is found at the version that caused it (AUD-135)'. Sampled in this round with bench.cpu_load(): [25.7, 32.3, 66.5, 62.4, 68.8, 77.4], so the machine was busy during the round itself. (quoted in round UNT-139)
- Impact: REQ-027 (urgent help within 100 ms) failed at v0.8.14. Its fix is confirmed only by invalid runs and a probe. The launch has been over its +25% tolerance at every measurement for three versions, and the log calls this load without valid evidence. The rule meant to catch a regression at its version (AUD-135) has caught nothing, because no run has been valid. A release cannot pass step 2 of the Release row as long as this is so. Confidence note: the launch rise may be load alone. That is not shown either way.
- Direction: Get one valid run (busiest load at most 32%) at the current version before 0.9.0, and re-baseline or open a regression item from it. Make bench report the busiest load before and after each run separately, so a busy reading caused by Chrome itself after page.close() can be told apart from a busy machine. State in AGENTS.md that an invalid run at a live move is a record only, and that the next valid run must compare against the last valid version.
