### RVW-002 - the operations lens of round [[UNT-010]]

**Re-checks of the previous round:** none in this lens's brief.

**What was checked and found right:** Previous round: the store holds no AUD- fragment and no fragment of kind "audit" (directory listing of docs/fragments and a grep for kind = "audit" both empty), so there was nothing to re-check. This is the line's first round (UNT-010, routing design_audit).

Checked and right (quoted this round):
- Storage failure path. settings.js wraps every access: `try { stored = JSON.parse(localStorage.getItem(key) || "{}") || {}; } catch { stored = {}; }` and `localStorage.setItem` is in try/catch with "the choice holds for this visit only". Each stored value is validated against config before use (`stored.rhythm in config.breathing.rhythms`, `typeof stored.tones === "boolean"`, `config.theme.choices.includes(stored.theme)`), so a malformed stored value cannot break boot. test_slice2 `test_blocked_storage_falls_back_to_defaults` covers the blocked case and `test_settings_round_trip_through_a_reload` covers the AGENTS.md round-trip rule.
- The test runner does not fail open. cmd_test prints "[FAIL] {file.name}: could not load" with a traceback, "[FAIL] ... holds no test_ function", and "[FAIL] no test files collected", and returns 1 on any failure. The health check proved this in a scratch folder (1 passed, 2 failed, RC 1).
- The cache list is checked both ways: test_offline `test_cache_list_matches_the_shipped_files` asserts "shipped but not cached" and "cached but missing" are both empty, and `test_the_app_works_offline_after_one_visit` reloads offline and opens the help dialog.
- Install is atomic: `cache.addAll(FILES)` rejects as a whole, so a partial cache is never activated.
- Screen teardown: breathe.js and bubbles.js keep a per-run object and check `state !== run` / `run !== current` before acting, and stop() clears timers and cancels the frame, so a stale timer from a left screen does nothing.
- crisis.js `deviceRegion` skips an unreadable language tag in try/catch and falls back to the uncurated-region path.
- cmd_clean removes only `output/` and `tools/**/__pycache__`; it never touches `input/` or `.venv`, as AGENTS.md says.
- build: `SIZE_LIMIT_BYTES = 150 * 1024` with "[FAIL] over the size limit" and RC 1; bench exits 1 on a missed target; the performance log has a dated checkpoint per slice (v0.5.0: launch 132 ms, response 9 ms, 95.0 KB).
- No CI is a documented decision (design decision 11: "CI/CD | None in v1"), so it is the rule, not a finding.
- The publish commit fdaac5c is local only (origin/main is 75e923f). It changes only docs and records (`git show --stat`: AGENTS.md, docs/...), no shipped file, and AGENTS.md says "Push at a release, or when the owner needs a build to test on the phone - never per commit". That agrees with policy.
- Every slice commit bumped version.js (0.1.0 to 0.5.0) together with its shipped changes, so the deployed v0.5.0 cache name is correct today.
- The check-manifests "inkscape is used and not declared" flag on Freelief is a catalog heuristic, not a real dependency: tool_catalog.toml has `detect_files = ["*.svg"]` for inkscape, icons/icon.svg holds no "inkscape" text (grep count 0), and make_icons.py renders with `p.chromium.launch(channel="chrome")`. The real undeclared dependency is Chrome (see the findings).

**Findings: 15.**
- Critical: Two other apps on the same origin delete Freelief's offline cache, and Freelief then fails to open offline until its next version
- High: One failed data fetch at launch leaves a blank page with no breathing guide and no urgent-help control
- Medium: A failed data load on a deep link to Standards stops the router, and from another screen it leaves a frozen guide
- Medium: The update test that the design relies on does not exist
- Medium: Nothing checks that a change to a shipped file comes with a version bump, so installed users can keep an old file indefinitely
- Medium: test and build check the working tree, not the commit that GitHub Pages deploys
- Medium: The browser that the tests, bench and icon tool need is not installed by setup, not checked by doctor and not declared
- Low: Test dependencies are installed without versions or a lock file
- Low: doctor reports the tests collectable after only counting files
- Low: doctor silently skips a JSON file that is missing
- Low: doctor does not check the service worker, though the design says it does
- Low: bench fails with a raw traceback when the .venv is missing
- Low: The worker's precache may read stale files from the browser HTTP cache and store them under the new version name
- Medium: Freelief's activate deletes every cache on the shared origin, not only its own
- Low: The breathing guide and the bubble field keep every timer id for the whole session

**Closing:** I cannot say "Sound as written". Two other apps on the effigymedia.github.io origin delete Freelief's offline cache, and I reproduced the result: after that delete, an offline launch shows a browser error page with no breathing guide and no help control (Critical). A single failed data fetch at launch gives a blank page (High). The update test that the design names as its offline-update mitigation does not exist, and nothing ties a change to a shipped file to a version bump.
