### AUD-058 - bench enforces only the hard targets, not the recorded tolerance, and launch and size are each 34% over baseline with no log entry since v0.5.10

- Severity: Low
- Area: D. Performance
- Evidence: Quoted in this round. docs/performance/baseline.md: 'Launch to first screen (REQ-026) | < 1000 ms | 155 ms | — | +25%, and never over target' and 'Shipped size ... 130.3 KB ... any growth is noted in the log'. This round's bench: 'Launch to first screen (REQ-026) 207.8 ms' (+34%) and 'Shipped size (REQ-028) 175.0 KB' (+34%), both printed [ OK ]. tools/bench.py compares only `ok = value <= target` with LAUNCH_TARGET_MS = 1000. The newest entry in docs/performance/log.md is '2026-10-07 — Re-baseline (v0.5.10)'; HEAD is v0.5.36. Performance_Testing.md section 4: a flagged metric 'can't ride along silently'. Confidence: one bench run, and the log notes 14 ms of run-to-run noise, so the launch figure may be 10 to 20% over rather than 34%. (quoted in round UNT-051)
- Impact: No user is hurt now: both figures are far inside their targets. But the regression signal the baseline exists for does not fire, so slow growth reaches a target before anyone looks, and 26 versions of added screens and sounds have no checkpoint.
- Direction: Have bench read the baseline median and tolerance (or hold them beside the targets) and print FLAG, without failing, when a metric is over tolerance. Run a checkpoint now, append the log entry, and either re-baseline with a stated cause or open an RLG- item for the launch growth.
- Effort: S
- Found by: the operations lens of round [[UNT-051]].
