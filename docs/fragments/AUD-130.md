### AUD-130 - The hostile-data test changes a `code` field that the crisis data does not use, so the escape of the region code, and of every config radio value on Settings, has no test that can fail

- Severity: Low
- Area: E. Security (input validation at a trust boundary)
- Evidence: Quoted in round UNT-124. tools/tests/test_safety.py HOSTILE_DATA: `const region = Object.values(data.regions || data).find((r) => r && r.country); if (region) { region.country += bad; region.code += bad; }`, and for config.json only `data.mandala.palette[0].name += bad;`. In data/crisis-lines.json a region has no `code` field: the code is the key (`"US": { "country": "United States", ... }`). crisis.js regionList takes the code from the key and ignores any field: `Object.entries(data.regions).map(([code, region]) => ({ code, country: region.country }))`. So `region.code += bad` changes nothing that screens/settings.js renders in `<option value="${escape(region.code)}">`. The config values that Settings writes into markup through `value="${escape(choice)}"` and `value="${escape(minutes)}"` come from `breathing.rhythmOrder`, `settings.openOnChoices`, `theme.choices` and `wakeLock.idleMinutesChoices`, and the test does not change any of them. UNT-120's close says the test 'rewrites the crisis data and config.json as they load, so that they carry markup'. Design section 9 says a sibling site on the shared origin 'can read and write Freelief's offline cache', so the cached data is a real trust boundary. (quoted in round UNT-124)
- Impact: A later edit that drops escape() from the region code or from a Settings radio value passes the whole suite. The design names a cache tampered by a sibling site as a known dependency. Such a cache could then put markup into the Settings page. The CSP still blocks script, so the reach is injected markup and links, for example a fake control beside the urgent-help region choice. The test reads as full coverage, and it is not.
- Direction: In HOSTILE_DATA, add a region under a hostile key, for example `data.regions['X"><b class="injected">x</b>'] = { ...region }`, in place of `region.code += bad`. Also append the marker to one entry each of `breathing.rhythmOrder`, `settings.openOnChoices`, `theme.choices` and `wakeLock.idleMinutesChoices`, and keep the matching `rhythms` entry so that the screen still starts. Show that the test fails when `escape(` is removed from settings.js, and record that as the unit's evidence.
- Effort: S
- Found by: the security lens of round [[UNT-124]].
