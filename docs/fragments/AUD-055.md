### AUD-055 - The Feedback page puts the person's whole message into the GitHub link's URL, so the text reaches browser history and GitHub when the link opens, before the person submits anything

- Severity: Low
- Area: E. Privacy & licensing
- Evidence: Quoted in this round (2026-10-08, HEAD b1a7858). screens/feedback.js updateLinks(): `issue.searchParams.set("body", message.value); github.href = issue.toString();`. It runs on every keystroke (`message.addEventListener("input", updateLinks)`). test_slice4.py asserts `query["body"] == [message.input_value()]`. The design chose this: F9 says "a new issue URL with the template, title and body in its query". strings/en.json `feedback.intro` says: "Nothing is sent by Freelief itself: you read and edit the message, then send it yourself." The person's understanding is that the send happens at GitHub's Submit button. In fact a press of "Open on GitHub" does a GET to github.com with the full text in the query string. Confidence: this comes from reading the code and from standard browser behaviour (a navigated URL is kept in browser history and is visible in server request logs). For a person who is not signed in, GitHub redirects to sign-in with the URL as the return target, so the text also passes through that redirect. No request was captured in this round. (quoted in round UNT-051)
- Impact: Some users are people in or near a panic attack, and the message box invites them to say what happened. If such a person types health details and then opens the link but does not submit, the text still stays in the browser history of a phone that may be shared, and it reaches GitHub. The person can see no sign of this. The reach is small: the person must type sensitive text and also press the button. It works against 'ask nothing, keep nothing', and the intro sentence makes the person expect less exposure than really occurs.
- Direction: Decide with the owner. Option 1: keep the body in the URL and extend the warning line that AUD-006 asks for, so that it says the message goes to GitHub, and into this browser's history, when the person opens the link. Option 2: send only the template and title in the URL, and give a 'Copy message' button that the person pastes into the issue. The text then never enters a URL. Record the choice in the design's F9 and the Decision Log. Change the feedback.intro wording to match, and change test_slice4.py to match the chosen behaviour.
- Effort: S
