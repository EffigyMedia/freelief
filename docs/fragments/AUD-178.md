### AUD-178 - The first release, v1.0.0, has no rollback target: the incident rule names the previous release tag, and none will exist

- Severity: Low
- Area: none - omission (the first time)
- Evidence: Quoted in round UNT-139. AGENTS.md Incident row: "The owner may move `live` back to the previous release tag at once ... `git push --force origin vPREVIOUS:live`." The Instruction Changelog: "An incident rolls `live` back to the previous `preview-` tag before 1.0, and to the previous release tag from 1.0." Design section 9: "from 1.0 each release is tagged `vX.Y.Z`, so the target always has a name (AUD-121)." `git tag` lists only preview- tags. Section 7 row 10 says that from 1.0, live moves "only at a release, after `audit-gate.py` prints `GATE CLEAR`, to a tag". No rule says whether a preview tag, which no gate cleared, is a valid target from 1.0. (quoted in round UNT-139)
- Impact: A defect in v1.0.0, such as a wrong crisis number, is an incident at the moment the app first reaches users widely. The owner then has either no named target or a target the rules forbid, and has to decide under pressure.
- Direction: State the first-release case in the Incident row and design section 9: before v1.0.1 exists, an incident in v1.0.0 rolls back to the newest preview- tag, with the reason recorded. Or name another target, by the owner's ruling.
