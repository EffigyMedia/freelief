### RVW-014 - the operations lens of round [[UNT-104]]

**Re-checks of the previous round:**
- [[AUD-057]] not done: Unchanged since round UNT-082. The second-window case is still open. app.js: `const inUse = () => interacted || document.querySelector("main")?.dataset.screen === "breathe"; const offerTakeover = (worker) => { if (worker && hadController && !inUse()) worker.postMessage("skip"); };`. Here `interacted` is the flag of the page that sends the message, and no other page is asked. sw.js still does `if (event.data === "skip") { self.skipWaiting(); return; }`. Its activate deletes every other `freelief-` cache and then runs `self.clients.claim()`. A fresh second window therefore still activates the new worker under a touched first window. That window then loads the new version's lazy screens from the new cache. The sw.js comment "A version never changes under a page the person is using, so an old page never loads new files (AUD-057)" is still false when two windows are open. `git log -S offerTakeover` shows no change after 19b9dff (v0.5.42) except the inUse() rename. No test opens a second window: a grep for clients.matchAll and for a second page in tools/tests found nothing. The hash part of the fix holds: show() runs `history.replaceState(history.state, "", `#${DEFAULT_ROUTE}`)` on a failed load. (quoted in round UNT-104)
- [[AUD-032]] partly done: This is the same state as round UNT-082. tools/freelief.py still has `PIP_PACKAGES = ("playwright==1.63.0", "axe-playwright-python==0.1.8")`, which is done. Three parts are still missing. (1) tools.toml is still `required = []`, `optional = []`, `retired = []`, and it declares no uv, Playwright, axe or Chrome. (2) cmd_doctor runs only `import playwright, axe_playwright_python` and prints no installed version. (3) No lock or hashed requirements file is tracked: `git ls-files | grep -iE 'requirements|lock|pyproject|uv\.'` matched only the unrelated activities/unblock.js, test_unblock.py and wakelock.js. So the transitive packages (greenlet, pyee, typing-extensions) are still unpinned. (quoted in round UNT-104)
- [[AUD-079]] partly done: Status is built, but the fix does not work. tools/bench.py has `BUSY_LOAD_PERCENT = 35`, and cpu_load() starts a new `powershell -NoProfile -Command "(Get-CimInstance Win32_Processor | Measure-Object -Property LoadPercentage -Average).Average"` for each sample. In round UNT-104 that exact probe read 72, 63, 65, 52, 66, 55 and 40. `typeperf "\Processor(_Total)\% Processor Time"` read 13 to 23% in the same minute, and its samples were taken a few seconds before each probe. The probe mostly measures the cost of starting PowerShell and CIM. As a result, bench refuses every run as [BUSY]. The health check's three runs did this (71/83/77%), and so did this round's run ('busiest CPU load 66.0%' while the counter showed about 16%). baseline.md blames 'other applications' for this load ('this machine stayed between 33% and 63% load'). The verdict still cannot tell a regression from a busy machine, which is the defect AUD-079 named. Now bench can only say 'not valid'. (quoted in round UNT-104)
- [[AUD-028]] partly done: Status is built, but the Direction ('Run ... at least the never-break tests: launch, help, offline, keyboard ... in Playwright WebKit and Firefox as well') is only partly met. tools/tests/test_engines.py has one test, `test_the_never_break_paths_work_in_webkit`. It calls `open_app(route=None, on=browser)`, and the default of open_app is `service_workers="block"`. So WebKit never runs the offline path. Every step uses `.click()`, so WebKit never runs a keyboard path. Firefox has no test at all. The module says 'Firefox joins when its engine can start on this machine (see RLG-033)'. Doctor warns about this ('[WARN] firefox cannot start here, so its browser tests do not run'), but `python tools/freelief.py test` printed '178 passed, 0 failed' and said nothing about Firefox. Design section 7 row 1 still names Firefox as a supported browser. (quoted in round UNT-104)

**What was checked and found right:** Checked and right in round UNT-104:
- Boot failure path. app.js `boot().catch(...)` puts the static fallback back (`document.body.replaceChildren(staticFallback)`). fallback.js reveals it after `REVEAL_AFTER_MS = 2000` when `dataset.ready !== "true"`, and the file documents why that constant is not in config.json.
- Crisis data. crisis.js loadCrisisLines() catches a failed load, logs it ("Freelief could not load the crisis lines:"), and keeps the directory link from config.json (`directory ? directory.url : config.crisis.directoryUrl`).
- Settings storage. settings.js wraps every localStorage access in try/catch. Its validators use Object.hasOwn and the config choice lists. The v1 to v2 migration and the `calmMode === "rain"` to "nature" migration handle an upgrade. Reset writes only `{}`.
- The removal story for a person. about.privacy2 says "Clearing your browser data removes them". Design section 9 says how to move or retire the site without stranding installed copies.
- The service worker. It deletes only `freelief-` caches. It answers only from its own version's cache (`caches.open(CACHE).then((cache) => cache.match(...))`). A Cache Storage fault falls back to the network (`.catch(() => fetch(event.request))`). The heal reply is heard (`event.data.heal === false` logs a warning). The cache cannot grow without limit: the worker stores only same-origin GET responses with `response.ok && response.type === "basic"`, and match uses `ignoreSearch`.
- The update flow for a single window. A new worker waits. offerTakeover and controllerchange respect inUse(), which includes a running breathing screen (AUD-107). Update now checks `navigator.onLine` and `registration.update()` before it deletes anything (AUD-056). It deletes only `freelief-` keys.
- The wake lock. A late grant is released, the lock ends after the idle time, and keepAwake() releases are idempotent.
- Timers. Every activity's stop() clears its timers and animation frames: bubbles, calm, ripple (cancelAnimationFrame), breathe and trace.
- AUD-087. The bench response probe now ends on a MessageChannel message posted from inside requestAnimationFrame, which runs after the paint.
- The tooling. The test runner fails on a file it cannot load ('[FAIL] {file.name}: could not load') and on a file with no test. `build --release` fails on uncommitted shipped files, a missing version bump, stale crisis data and outdated standards. `files` compares sw.js FILES with the shipped files.
- The Release row. It now runs prepare, validate, gate, tag, and deploys last. The Incident row gives a rollback command.
- I re-ran bench once (exit 2, BUSY by its own probe): launch 187.6 ms (OK), response 93.9 ms (FLAG), size 238.6 KB (FLAG).
- The working tree was unchanged after every run. Only the scratch probes and output/bench.json were written.
