### AUD-070 - The accessibility-check checklist names a 'More ways to calm' screen that no longer exists and lists none of the activities, and nav.settingsHint outlived the menu change unused

- Severity: Low
- Area: F. User experience
- Evidence: Quoted in round UNT-051. strings/en.json "feedback.template.accessibility" and .github/ISSUE_TEMPLATE/accessibility-check.md: "[ ] Breathing screen / [ ] Need urgent help / [ ] More ways to calm, and each exercise / [ ] Settings / [ ] About, Standards and research, Feedback". No control or screen with that label exists: the menu heading is "What would help right now?", and every screen has only "Back to menu". The checklist does not name bubbles, trace, sort, ripple, mandala or the Visualizer and its black screen. REQ-029 needs a manual check of what is shown as met. Separately, "nav.settingsHint": "Breathing rhythm, sounds and colors." has no reader in the code, because screens/menu.js ITEMS no longer holds Settings ("Settings is the gear at the top right, not on this list"). (quoted in round UNT-051)
- Impact: A volunteer who fills in the accessibility check looks for a control that is not there, and a check made from this list cannot show that every screen was checked. That is the evidence REQ-029 needs before a WCAG claim, and AUD-054 already notes that 'every page' is undefined. The unused string is dead weight in the one strings file.
- Direction: List the menu and each activity by its shown name in both templates (for example "[ ] The menu, and each exercise and activity" expanded per route), and keep the list in step with the menu routes; a test could compare the template lines with the menu's route list. Delete nav.settingsHint. Add a repo test that every key in strings/en.json is read somewhere, with an allowlist for keys that are built at run time.
- Effort: S
