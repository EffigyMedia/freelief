### AUD-031 - No test guards the CSP, and the static external-load check misses common forms

- Severity: Low
- Area: E. Security
- Evidence: AGENTS.md: "Nothing ships that loads from another origin ... `test_repo.py` enforces both". `grep -rnIl 'Content-Security' tools/tests` returned nothing, so no test fails if the CSP meta is removed or loosened. The `EXTERNAL_LOAD` regex was run over sample lines and returned False for each of `import * as x from "https://cdn.example/x.js";`, `await import("https://cdn.example/x.js")`, `<img src="https://t.example/p.gif">`, `new Worker("https://x/y.js")`, ``fetch(`https://x/y`)`` and `navigator.sendBeacon('https://x', d)`. The runtime foreign-request assertions cover only launch (`test_app.py`) and the Feedback page (`test_slice4.py`). (quoted in round UNT-010)
- Impact: A later change could load third-party code or send data from a screen the tests do not open, with the CSP loosened in the same commit, and every test would pass. That would break REQ-015 and REQ-019, the app's central privacy promise.
- Direction: Add a test that parses the CSP meta in `index.html` and asserts the exact allow-list (no non-self source, no 'unsafe-inline' or 'unsafe-eval'). Widen the static check to any `https?://` in shipped JS and HTML outside an allow-list of link targets (crisis lines, directory, sources, GitHub). Or assert foreign requests while every route is opened.
- Effort: S
