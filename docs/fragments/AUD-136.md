### AUD-136 - build --release proves that version.js changed, not that the version number rose

- Severity: Low
- Area: H. Build & deployment readiness
- Evidence: Quoted in this round. tools/freelief.py changed_since_version_bump(): 'bump = git("log", "-1", "--format=%H", "--", "version.js").strip()' and then 'git diff --name-only bump HEAD'. Any commit that touches version.js counts as the bump, including a change to its comment only. Nothing compares FREELIEF_VERSION with the previous commit's value or with the last preview or release tag. sw.js names its cache from the number: 'const CACHE = `${PREFIX}${self.FREELIEF_VERSION}`'. (quoted in round UNT-124)
- Impact: If a commit edits only the comment in version.js, or keeps the same number, the release check passes. Installed copies then keep the same cache name, so the new files either never reach them or are refetched into the cache that a running old page uses. The check exists to catch exactly this case (AUD-010), and it passes falsely.
- Direction: In build --release, read FREELIEF_VERSION at the last tag (preview-* or v*) and at HEAD, and fail unless HEAD's version is higher. Locate the bump with 'git log -G FREELIEF_VERSION' instead of any change to the file. Add a test_repo case for a comment-only change.
- Effort: S
