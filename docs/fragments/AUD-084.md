### AUD-084 - A failed crisis-lines load is swallowed with no log, so a field report of 'no lines in urgent help' cannot be debugged

- Severity: Low
- Area: C. Logging & diagnostics
- Evidence: crisis.js (quoted in round UNT-082): `} catch { data = null; }` around `fetch("data/crisis-lines.json")`, with no console call. Every other start-up failure is logged: app.js `console.error("Freelief could not start:", error)` and `console.error(`Freelief could not load the ${name} screen:`, error)`. With `data = null`, the dialog shows only `help.emergencyUnknown` and the directory link, and it has no country list. test_startup.py test_a_failed_crisis_file_keeps_the_guide_and_the_emergency_route checks the fallback route but not any diagnostic. (quoted in round UNT-082)
- Impact: This is the most safety-critical data in the app. When it fails to load (a damaged cache offline, or a bad deploy), the person sees no curated lines and no reason. A later session that gets the report finds nothing in the console to tell this failure from 'region not curated'.
- Direction: Log the failure with the reason, for example `console.error("Freelief could not load the crisis lines:", error)`. Assert in the start-up test that the error is logged.
- Effort: S
- Found by: the operations lens of round [[UNT-082]].
