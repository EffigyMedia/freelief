### AUD-003 - Any push to main is a public deploy, but the rules call a phone-test push 'not a release', so the audit gate never applies to what users get, and v0.5.0 is live without a round

- Severity: High
- Area: A. Design alignment
- Evidence: Quoted in round UNT-010. AGENTS.md: "GitHub Pages serves `main` at `https://effigymedia.github.io/freelief/`, so **a push is a deploy.** Push at a release, or when the owner needs a build to test on the phone". The standing policy says: "An actual release is a version that reaches this project's users, and a build pushed only for testing is not one." Audit_and_Testing.md section 11: "A build pushed only for testing is not one, and a project names in its own `AGENTS.md` anything else that is not." docs/README.md (commit fdaac5c) tells the public: "Open the app in a browser: <https://effigymedia.github.io/freelief/>. To install it, use your browser's \"Add to Home Screen\"". The health check found that origin/main is 75e923f (v0.5.0) and that the Pages build is 'built'. `gh api .../pages` returns source main "/". The live version.js is "0.5.0". `git tag` prints nothing. The store holds no AUD- or review fragment, so no round ran before that push (UNT-009 closed before UNT-010 opened). (quoted in round UNT-010)
- Impact: The test build and the release are one public URL. Every build pushed 'for the phone' reaches real users in a crisis app, and the service worker installs it on their devices with no gate. Today v0.5.0 is advertised to users with no gate, no tag and no formal crisis-line re-check. The gate that the standing policy requires cannot hold while main is both the test channel and the production channel.
- Direction: The owner rules on one model, recorded in the Decision Log, AGENTS.md and the Instruction Changelog. Either (a) every push to main is an actual release and passes audit-gate.py first, and phone tests are served from somewhere that is not the advertised URL (a separate branch or repository that is not advertised); or (b) state plainly that versions before 1.0 on Pages are test builds, and remove the install invitation from the README until 1.0. Remove the sentence that allows a phone-test push to main. Then tag what is live now, or record why it is not tagged.
- Effort: M
- Found by: the whole-design and omission lenses of round [[UNT-010]] - convergence.
- **RULED 2026-10-07T14:46:08-04:00** — Attempt 1, UNT-013: the owner chose a separate live branch. Branch live was created at 75e923f (the v0.5.0 already deployed) and pushed; GitHub Pages now serves live (gh api .../pages source: {branch: live, path: /}). Pushing main deploys nothing. AGENTS.md (Deploy, Conventions, Release), the Instruction Changelog and the Decision Log state the model: before 1.0 live is a public preview moved only with the owner's yes; from 1.0 on it moves only at a release that cleared audit-gate.py, to a tag. The sentence allowing a phone-test push to main is replaced. docs/README.md now says the app is a preview and does not invite installs. v0.5.0 on live is a preview, not a release, so it is not tagged; the Decision Log says why. A later round confirms.
