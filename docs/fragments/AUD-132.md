### AUD-132 - AUD-057 recurs: a touch after the page offers the takeover still lets a new version take over a page in use, delete its cache and serve it the new version's screens

- Severity: Medium
- Area: C. Regression risks
- Evidence: Quoted in this round. app.js checks use only when it posts: 'const offerTakeover = (worker) => { if (worker && hadController && !inUse()) worker.postMessage("skip"); };'. On 'controllerchange' it reloads only 'if (hadController && !inUse() && !reloaded)'. sw.js decides from the window count only: 'const alone = windows.every((client) => client.id === event.source?.id); if (alone) return self.skipWaiting();'. activate then deletes every other 'freelief-' cache and calls clients.claim(). So a touch that lands after the skip message and before controllerchange leaves an old page with no reload under the new worker. The sw.js comment says the opposite: 'A version never changes under a page the person is using, so an old page never loads new files (AUD-057).' A scratchpad probe on a temporary copy installed v0.8.14, touched the page, deployed 9.9.7 with a renamed mandala start, and delivered the skip message after the touch. It printed 'page version: 0.8.14', 'old cache kept: False', 'controller script version cache: ['freelief-9.9.7']', then 'shown: menu hash: #menu' for '#mandala'. The old shell loaded the new mandala.js and fell back to the menu. No test covers this order: test_an_update_reloads_the_page_onto_the_new_version_before_any_touch and test_after_a_touch_a_new_version_waits_and_the_session_keeps_its_own_files each cover only one side of it. (quoted in round UNT-124)
- Impact: The window is short: the worker starts, activates and deletes the old cache. But it opens at launch, which is exactly when a person in panic taps Breathe. The tapped screen loads from the new version into the old shell. If its contract, its config keys or its strings changed, it bounces to the menu, or it shows raw string keys until the next open. The offline copy of the old version is already deleted.
- Direction: Record this against AUD-057 as a further attempt, not as a new defect. Let the page withdraw its offer: on the first touch, if a skip was posted, post 'stay', and let the worker refuse a 'skip' that arrives after a 'stay'. Or let the page reload on controllerchange only when it is not in use, and otherwise keep the old cache until the page closes. A simpler choice is to delete old caches only at the next activation that finds no old client. Add a test that touches between the skip message and controllerchange, as the probe did.
