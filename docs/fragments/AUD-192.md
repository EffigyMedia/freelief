### AUD-192 - Every Update now failure says 'This version still works offline', even when Settings shows on the same screen that the offline copy is not saved

- Severity: Low
- Area: none - omission (an error message that does not consider one state); F. User experience (tone: errors say what still works)
- Evidence: strings/en.json: '"settings.updateFailed": "Could not update. This version still works offline."'. screens/settings.js shows this text after a failed registration.update(), after a 'redundant' worker, and after a 'timeout' or false refresh. It does this without asking whether the copy is whole. The same screen shows offlineState(), which can be 'NotReady': '"settings.offlineNotReady": "This version is not saved for use with no internet yet. Open Freelief once while online."'. That happens, for example, when a sibling site on the shared origin deleted the cache (AUD-001) and the repair has not finished. Design section 6, Tone of voice: 'Errors are calm and say what still works.' (quoted in round UNT-155) (quoted in round UNT-155)
- Impact: After a failed update, a person whose offline copy is incomplete is told that it works offline. They may go offline trusting it and then find that Freelief does not open. The two lines on one screen also contradict each other, which costs trust.
- Direction: After a failure, ask the worker for 'status' (as offlineState does). Show settings.updateFailed only when the copy is whole. Otherwise show a new string, for example 'Could not update. Open Freelief again while online to finish saving it.' Add a test with an incomplete cache.
- Effort: S
- Found by: the omission lens of round [[UNT-155]].
