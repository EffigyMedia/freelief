### AUD-033 - Pages build HTML from data with escaping that is not consistent

- Severity: Low
- Area: E. Security
- Evidence: screens/standards.js defines `escape()` and applies it to `source.url` and `source.citation`. It does not apply it to `data-technique="${technique.id}"` or to `t("standards.checked", { date: source.checked })`, which go into `container.innerHTML` raw. screens/about.js inserts `href="${config.project.sourceUrl}"` raw. The CSP blocks inline script, so the reach is markup only. Confidence: no hostile value is in the data today. This is a hardening gap, not an exploit. (quoted in round UNT-010)
- Impact: A bad edit to `data/research.json` or `config.json` can inject markup into a trust page, with no review on `main` (see the reviewed-commit finding). For example, it could insert a misleading link next to the research sources.
- Direction: Escape every data value that goes into `innerHTML`, or build these pages with the `textContent` helper that `app.js` already uses.
- Effort: S
- Found by: the security lens of round [[UNT-010]].
