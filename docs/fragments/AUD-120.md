### AUD-120 - A cache miss or a heal fills the running version's cache from whatever version is deployed now, so one cache can hold two versions

- Severity: Low
- Area: C. Regression risks
- Evidence: sw.js fetch handler: on a miss, `return fetch(event.request).then((response) => { ... cache.put(event.request, copy) ...` into `CACHE = `${PREFIX}${self.FREELIEF_VERSION}``. The heal handler runs `cache.addAll(missing.map((file) => new Request(file, { cache: "reload" })))` into the same CACHE. Neither checks that the network serves this version. The same file states the hazard: 'while an old version's cache still exists it can serve old files to a new version, or a mix of both, and the app may not start'. app.js posts 'heal' to `registration.active` on each online launch. This happens before a waiting new version takes over, and it never happens while the page is in use. Confidence: found by reading the code, and not probed. It needs a partly deleted cache (AUD-001) and a newer deploy at the same time. (quoted in round UNT-104)
- Impact: This hurts a person whose offline copy was partly deleted by a sibling app on the shared origin, after a new version is live. The old worker refills the gaps with new files under the old cache name. The shell can then fail to link a module, or show raw string keys. This can persist while the page is in use, or in a second window (AUD-057).
- Direction: Before it stores a network response for a miss or a heal, the worker should confirm that the deployed version is its own. For example, fetch version.js with cache 'reload' and compare FREELIEF_VERSION. On a mismatch, serve the response without storing it, and leave the repair to the new worker. Add a test: delete one lazy file from the cache, deploy 9.9.x, launch online, and assert that the old cache holds no new file.
- Effort: M
- Found by: the operations lens of round [[UNT-104]].
- **RULED 2026-10-10T11:31:15-04:00** — 2026-10-10 (UNT-122, v0.8.13): fixed as the Direction said. sw.js thisVersionIsDeployed() fetches version.js with cache 'reload' and compares FREELIEF_VERSION; the fetch handler stores a miss, and heal refills missing files, only when it matches. On a mismatch the response is served but not stored, and heal stores nothing and replies true. test_a_newer_deploy_is_never_stored_in_the_running_versions_cache deletes calm.js from the cache, deploys 9.9.8, opens #calm and posts heal, asserts the old cache still has no calm.js, then serves the old version again and asserts heal refills it. It fails against the old sw.js. Cost: one small version.js request per online launch and per miss.
